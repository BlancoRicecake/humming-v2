# HumTrack 로드맵 컨텍스트 노트

결정과 그 이유를 날짜순으로 쌓는다. 다음 세션은 여기부터 읽는다.

## 2026-10-12 — 비전·로드맵 수립

**비전 (Heo)** — 음악을 좋아하는 누구나 비싼 장비 없이, 비용 걱정 없이 취미로든 업으로든 꿈을 펼치는 공간.

**결정**
- 첫 작업은 비전·로드맵 정리. 개발은 이 문서 기준으로 진행한다.
- 우선 사용자는 **취미 초보자**. 업 지망생 기능(데스크톱, DAW 연동 고도화)은 나중.
- 수익은 **현 구독 구조 유지** (월 ₩5,500 / 연 ₩55,000, 무료 4곡, 내보내기 Pro).

**근거로 본 현재 상태**
- 앱 버전 `1.0.10+39`. 로컬 HEAD는 `codex/humtrack-desktop`.
- guided creation(`codex/humtrack-guided-creation`), 반주 후보·곡 구성(`codex/humtrack-songplan`)은 구현·에뮬레이터 검증까지 됨. 실사용자 검증은 아직.
- Firebase 분석은 코드·설정 완료, 프로덕션 수집은 게이트 미통과로 꺼져 있음.
- 9월 말~10월 초에 Android 로그인 설정 누락 빌드, iOS 1.0.9 실행 크래시가 있었고 모바일 Sentry는 30일간 0건이었음 → Phase 0를 "기반 다지기"로 둔 이유.

**판단**
- 새 기능보다 Phase 0(브랜치 일원화, 모니터링, 분석 수집)를 먼저 둔다. 데이터 없이 개선하면 추측 기반이 된다.
- 데스크톱 작업은 현재 HEAD지만 초보자 첫 곡에 기여하지 않으므로 "나중"으로 분류했다. 이어서 할지 멈출지는 Heo 확인 필요.
- 무료 사용자가 곡을 밖으로 꺼낼 수 없는 점이 비전("비용 걱정 없이")과 가장 크게 부딪힌다. 구독은 유지하되 무료 "들려주기" 여부를 Phase 3에서 데이터로 결정하기로 열어 둠.
- 북극성 지표(첫 곡 완성률, 두 번째 곡 비율)는 Claude 제안이며 Heo 확정 전.

**확인 못 한 것** — git 브랜치 병합 상태, 스토어 실시간 상태, 정책 1.4 고지 발송 여부 (이번 점검은 문서·코드 정적 확인만).

## 2026-10-12 — 데스크톱 병행 결정

**결정 (Heo)** — 데스크톱도 모바일과 같이 진행한다. 앞서 "나중"으로 뒀던 분류를 뒤집고 로드맵 5장에 데스크톱 트랙(D1–D4)을 추가했다.

**근거** — `DESKTOP-PROTOTYPE-2026-09-18.md` 기준 Windows는 소리·내보내기·저장·키보드 연주·단축키·타임라인 확대까지 검증된 프리뷰가 있다. 남은 건 대부분 기능이 아니라 출시 조건(로그인, 결제, 실마이크, 서명·설치)이다. macOS는 코드·권한만 준비됐고 Mac에서 한 번도 실행되지 않았다.

**판단**
- 데스크톱 결제는 "모바일 구독 계정으로 로그인하면 Pro"(A안)가 가장 적은 구현으로 보이나 Heo 결정 전.
- desktop 브랜치는 9월 18일 guided-creation 위에 만들어져서, 이후 출시 브랜치의 수정이 빠져 있을 가능성이 크다. 그래서 D1을 Phase 0 브랜치 정리에 묶었다.
  - 정정 (같은 날, 인프라 검토 중): reflog상 로컬 desktop은 10-05에 origin/main으로 fast-forward됐다. 남은 의문은 "출시 브랜치들이 main에 들어갔는가"로 좁혀졌다.

## 2026-10-12 — 초심: 왜 하는가 (Heo)

- 이유: Heo는 음악적 재능은 없지만 음악을 사랑한다. 재능 있는 사람이 음악을 못 하는 가장 큰 이유는 경제적 문제라고 본다. 그걸 해결한다.
- 만들 것: 초보자가 쉽게 만들고 편집하고 가지고 노는 DAW → 재능 있는 사람들이 모여 곡·노래·뮤직비디오·앨범 커버를 함께 만드는 공간.
- **글로벌 타깃. 한국에 국한하지 않는다.**
- 요청: 경쟁사·오픈소스·유사 서비스를 전부 조사해 판단의 배경 지식으로 보유하고, 주기적으로 갱신하며, 큰 결정 전에는 다시 찾아볼 것. → `docs/knowledge/` 생성 (5개 영역 조사, 핵심 시사점 26개).
- 조사가 기존 결정에 던진 질문 (결정은 Heo): 무료 내보내기 정책, 첫 글로벌 시장(일본 유력), 지역별 가격. `docs/knowledge/insights.md` A·B·G.
- **결정 (Heo)**: 배경 지식은 매달 자동 갱신 (예약 작업, 매월 1일). 무료 내보내기 문제는 원래 계획대로 **Phase 3에서** 다룬다. 단 Phase 3 직전에 `insights.md` B절을 재조사한다.

## 2026-10-12 — 조사로 드러난 기존 판단 2개 처리 (Heo)

- **YuE → 실험 후보.** 라이선스는 Apache-2.0으로 바뀌었지만 학습 데이터 출처 불명, 24GB GPU 필요, "내 멜로디" 원칙 때문에 출시 관문은 통과 못 함. 내부 계정(`ARRANGEMENT_ENABLED=1`)에서만, AI 표시 붙여 실험 가능. `docs/AI_ARRANGEMENT_ROADMAP.md` 정정.
- **FluidSynth LGPL → 지금 고지 보강.** 앱 '오픈소스 라이선스' 화면에 FluidSynth 고지·LGPL 전문, 그리고 같이 빠져 있던 Avicii Pluck(CC BY 3.0) 크레딧 등록. 코드는 Cowork에서 작성, 빌드·테스트·전문 파일 추가·Android 동적 라이브러리 확인은 VS Code에서.

## 2026-10-13 — 음악 제품 검토와 개선 계획 문서화

**요청 (Heo)** — 작곡·프로듀싱 전문가 관점의 보고서를 프로젝트 문서로 남기고 기존 로드맵에 연결한 우선순위별 개선 계획과 개발 체크리스트를 만들 것.

**반영**

- [제품 검토](MUSIC-PRODUCT-REVIEW-2026-10-13.md): 창작·작곡·편곡·프로듀싱의 역량과 초보자/입문자/중수/고수, 기존 기능·부족한 부분·축약·후순위를 정리.
- [개선 계획](MUSIC-IMPROVEMENT-PLAN.md): M0 결과 신뢰 → M1 첫 창작 단순화 → M2 멜로디 보존 → M3 완성과 전달을 기존 Phase 0~3에 연결. 작업 ID·의존 관계·담당 영역·완료 기준을 정의.
- [개발 체크리스트](music-checklist.md): 상태의 단일 관리 위치. 기존 상위 로드맵·체크리스트는 링크로 연결해 진행 상태의 이중 관리를 피함.

**근거** — `a6db6ed`, 앱 `1.0.13+43` 정적 확인. 일반 MIDI 내보내기의 스윙 누락, 다중 효과 일부 삭제 후 오디오 재처리 부재, 고정 화음과 멜로디 첫 음 기반 베이스, 음표별 강약·미세 타이밍 부재, 직접 허밍의 강한 키/그리드/음역 매핑을 검토에 반영. 청취 품질·인식 정확도·스토어 제공 상태는 이 문서화로 검증된 것이 아니다. 지식 근거는 [insights.md의 A2·C8·D13·F26](../knowledge/insights.md), 교육·기능 근거는 보고서의 공식 자료와 코드 링크.

**계획 범위** — 기존 취미 초보자 우선, 단계 완료 기준, 데스크톱 병행, Phase 3 무료 공유 결정, AI 내부 실험 정책을 유지. 같은 날 확정된 [약속 Pro 기능](PROMISED-FEATURES-PLAN.md)의 현재 착수·수동 백업·보컬 옵트인·우선 분석·고지·출시 조건을 밀어내지 않음. M0 국소 결함 수정은 병행 가능하나 음악 개선 전체를 약속 기능 출시의 추가 필수 조건으로 삼지 않음.

**남은 설계** — 보정 기본값, 효과 취소 방식, 펜타토닉 화음 기준, 화음/꾸밈 저장 역할, 강약·타이밍 단위, 스테레오·스템 음량 정책은 작업별 설계와 재현 결과에 따라 확정. 기능 구현·실기기 검증은 미완료이며 체크를 미리 완료 처리하지 않음.

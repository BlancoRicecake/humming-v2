## 1. 왜 하는가, 무엇을 만드는가 (Heo, 2026-10-12)

> 모든 결정은 이 장으로 돌아와 확인한다.

**왜** — Heo는 음악적 재능은 없지만 음악을 정말 사랑한다. 세상에는 재능이 있는데도 음악을 하지 못하는 사람이 많고, 그 가장 큰 이유는 **경제적인 문제**라고 본다. HumTrack은 그 문제를 해결한다.

**무엇을** — 초보자가 음악을 정말 쉽게 만들고, 편집하고, 가지고 노는 DAW. 그리고 나아가 재능 있는 사람들이 모여 **함께 노는 공간**. 누군가는 곡을 만들고, 누군가는 노래하고, 누군가는 뮤직비디오를, 누군가는 앨범 커버를 만든다.

**누구에게** — **처음부터 글로벌.** 한국에 국한하지 않는다.

한 줄로: **음악을 좋아하는 누구나, 비싼 장비 없이, 비용 걱정 없이 자신의 꿈을 펼치는 공간.**

배경 지식(경쟁사·오픈소스·시장·법률)은 [`../knowledge/README.md`](../knowledge/README.md). 큰 결정 전에는 이 지식이 오래되지 않았는지 확인하고, 필요하면 다시 조사한다.

## 2. 지금의 초점 (결정됨)

| 항목 | 결정 | 의미 |
|---|---|---|
| 우선 사용자 | **취미 초보자** | 음악 이론·DAW·장비 없이 "내 멜로디로 첫 곡"을 만드는 경험에 집중한다. 업 지망생 기능은 뒤로 미룬다. |
| 수익 구조 | **현 구독 유지** | 월 ₩5,500 / 연 ₩55,000, 7일 체험. 무료 4곡, WAV·MIDI·스템 내보내기는 Pro. |
| 데스크톱 | **모바일과 병행** (2026-10-12) | 5장의 데스크톱 트랙으로 따로 진행한다. "비싼 장비 없이"를 PC 사용자까지 넓힌다. |

## 3. 북극성 지표 (제안)

- **첫 곡 완성률** — 앱을 처음 연 사람 중 첫 세션에서 곡을 저장한 비율 (`guided_song_saved` / `app_started` 신규)
- **두 번째 곡 비율** — 첫 곡을 만든 사람 중 7일 안에 두 번째 곡을 만든 비율. "다시 꿈을 펼치러 오는가"를 본다.

구독 전환율은 위 두 지표의 결과로 본다. 두 지표가 오르지 않는데 전환율만 올리는 작업은 우선하지 않는다.

## 4. 비전과 현재 구조의 긴장 (열린 질문)

**무료 사용자는 자기가 만든 곡을 앱 밖으로 꺼낼 방법이 없다.** 내보내기가 전부 Pro이기 때문이다.
"비용 걱정 없이 꿈을 펼치는"의 핵심은 *만든 걸 누군가에게 들려주는 순간*인데, 지금은 그 순간이 결제 뒤에 있다.

구독 구조는 유지하되 아래 중 무엇을 고를지 Phase 1 데이터를 보고 결정한다.

- A. 현행 유지 — 무료는 앱 안에서만 듣기
- B. 무료 "들려주기" — 짧은 음원(예: 30초, 워터마크·로고)을 SNS·메신저로 공유. 파일 원본·MIDI·스템은 Pro
- C. 무료 곡 수·기간 조정

B는 마케팅 채널(틱톡·릴스 유입)과도 맞물린다. 서버 비용은 허밍 분석 횟수에 비례하므로, 무엇을 열든 분석 호출량을 함께 본다.

## 5. 단계와 완료 기준

각 단계는 **완료 기준을 통과해야 다음으로 넘어간다.** 날짜보다 기준이 우선이다.

음악 개선의 M0~M3는 아래 Phase의 세부 우선순위다. M0는 결과 신뢰(MIDI 스윙·효과 취소·반주 표시), M1은 첫 창작 단순화, M2는 멜로디 보존, M3는 반주·표현·전개·전달에 연결한다. [세부 작업과 의존 관계](MUSIC-IMPROVEMENT-PLAN.md)

2026-10-13에 결정한 [클라우드 백업·보컬 보관·우선 분석 착수와 출시 조건](PROMISED-FEATURES-PLAN.md)을 유지한다. 음악 개선 전체를 해당 출시의 새 필수 조건으로 추가하지 않는다.

### Phase 0 — 기반 다지기 (지금)

새 기능보다 먼저, 데이터를 볼 수 있고 출시가 안전한 상태를 만든다. 최근 한 달 사이 Android 로그인 누락 빌드, iOS 1.0.9 실행 즉시 크래시가 있었고, 모바일 Sentry는 30일간 이벤트 0건이었다.

- 흩어진 브랜치(`desktop`, `songplan`, `guided-creation`, `login-hotfix`, `fix/ios-firebase-plist`)의 병합 상태를 확인하고 출시 기준 브랜치를 하나로 정한다.
- Sentry·Clarity가 실제로 이벤트를 받는지 양 플랫폼에서 확인한다.
- Firebase 분석 프로덕션 게이트(정책 1.4 고지, 스토어 폼, DebugView 검증)를 마친다.

음악 기능 연결: [M0-01~03](music-checklist.md#m0-결과-신뢰와-phase-0-연결)의 현행 결함을 재현하고 국소 수정한다. 기존 인프라 안정화와 병행하며, 각 음악 기능의 출시 전 표시·재생·출력 일치를 확인한다.

**완료 기준** — 기준 브랜치 하나에서 양 플랫폼 스토어 빌드가 나오고, 첫 곡 퍼널(`app_started → recording_started → analyze_completed → guided_song_saved`)을 1주일치 데이터로 볼 수 있다.

### Phase 1 — 3분 안에 첫 곡

이미 만든 guided creation(분위기 반주 Calm/Bounce/Drive, A·B·C 후보, 곡 구성)을 실제 사용자에게 보낸다.

- guided 흐름을 첫 실행의 기본 경로로 둔다. 상세 편집기는 유지한다.
- 초보자 5명을 직접 관찰한다(설명 없이, 화면 녹화).
- 막힌 지점을 고치고 다시 관찰한다.

음악 기능 연결: [M1-01~02](music-checklist.md#m1-첫-창작-단순화와-phase-1-연결)의 입력·검토·반주·저장 용어와 추천 음색·후보 비교를 사용자 관찰에 따라 다듬는다. 원본 비교·Undo·상세 편집 접근은 유지한다.

**완료 기준** — 초보자 5명 중 4명이 도움 없이 3분 안에 첫 곡을 저장한다. 퍼널 데이터에서 가장 큰 이탈 단계를 특정했다.

### Phase 2 — "내가 부른 멜로디가 맞다"

허밍 변환을 신뢰할 수 있어야 두 번째 곡이 나온다.

- 동의받은 허밍으로 고정 평가 세트를 만들고(튜닝용/확인용 분리) 음정·옥타브·분할·타이밍 오류를 따로 집계한다.
- 엔진 교체가 아니라 현재 pYIN 경로의 오류 유형부터 좁힌다.
- 틀린 음을 한 번에 고치는 경험(옥타브·분할·병합)을 다듬는다.

음악 기능 연결: [M2-01~03](music-checklist.md#m2-멜로디-보존과-phase-2-연결)의 원본 데이터·보정 선택·표시 음역 독립·선택음 자유 수정을 포함한다. 낮은 신뢰도뿐 아니라 사용자가 지목한 음도 수정할 수 있게 한다.

**완료 기준** — 평가 세트에서 오류율 기준선 대비 개선 수치가 있고, 사용자당 수동 수정 횟수가 줄었다.

### Phase 3 — 완성하고 들려주기

- 4장의 열린 질문(무료 들려주기)을 결정하고 구현한다.
- 반주 프리셋의 품질과 다양성을 늘린다.

음악 기능 연결: [M3-01~05](music-checklist.md#m3-완성하고-들려주기와-phase-3-연결)의 멜로디 기반 화성·베이스, 강약·그루브, 구간 전개·끝맺음, 밸런스·스테레오 전달, 작은 창작 학습을 패키지별로 검증한다. 전문 DAW 전체 재현은 현재 범위에 포함하지 않는다.

**완료 기준** — 두 번째 곡 비율이 Phase 1 대비 올랐다.

### 데스크톱 트랙 (병행)

`codex/humtrack-desktop` 브랜치에 이미 상당 부분이 있다 (`DESKTOP-PROTOTYPE-2026-09-18.md`, `MAC-HANDOFF-2026-09-18.md`).

**이미 된 것 (Windows에서 검증)**
- WASAPI PCM 출력으로 모바일과 같은 SoundFont 악기 재생, WAV·MIDI 내보내기, 편집 저장
- 가이드 창작·반주 생성 (guided-creation 커밋 위에 만들어짐)
- 키보드로 악기 연주 (키 배치 변경·저장), Space 재생, Ctrl+S/Z/Shift+Z, 녹음 단축키
- 타임라인 확대(100–400%)·가로 스크롤, 타임라인/패드 비율 드래그 조절
- 다크 창 테두리, 최소 창 960×600, 서명 없는 Windows 프리뷰 zip
- Flutter 테스트 162개 통과

**아직 안 된 것**
- 로그인 — 데스크톱 OAuth 콜백 미등록, 프리뷰에는 운영 인증 설정이 없음
- 결제 — Windows/macOS 구독 구매 경로가 없음 (아래 열린 질문)
- 실제 마이크 녹음 품질·지연, 장시간 사용, 출력 장치 전환, 절전 복귀
- Windows 코드 서명·설치 프로그램, 깨끗한 PC 배포 테스트
- macOS 빌드·소리·마이크·로그인·서명·공증 전부 (Mac 필요)
- 로컬 desktop 브랜치는 10-05에 origin/main으로 fast-forward됐지만, 로그인 핫픽스·iOS 크래시 수정·first-song-funnel이 main에 들어갔는지는 미확인 → Phase 0 브랜치 정리와 함께 처리 (`docs/devinfra/`)

**열린 질문 — 데스크톱 결제**
- A. 모바일에서 구독한 계정으로 로그인하면 데스크톱에서도 Pro (데스크톱 자체 결제 없음)
- B. 데스크톱 무료 프리뷰로 시작, 결제는 나중
- C. Mac App Store / 웹 결제 별도 구축

A가 구현량이 가장 적고 "한 구독으로 어디서든"이 된다. 서버 권한(entitlement)은 이미 계정 기준이라 로그인만 되면 연결 가능성이 높다 — 확인 필요.

**단계**
- D1. 브랜치 정리 후 Windows 프리뷰를 최신 main 기준으로 다시 빌드
- D2. Windows 로그인 + 계정 기반 Pro 연동, 실제 마이크 녹음 검증
- D3. Windows 서명·설치 프로그램 → `hum-track.com` 다운로드 공개
- D4. Mac에서 빌드·실기기 검증 → Developer ID 서명·공증 프리뷰

**완료 기준 (D1–D3)** — 깨끗한 Windows PC에서 설치 → 로그인 → 허밍 녹음 → 가이드로 첫 곡 → 저장 → 재실행 → (Pro 계정) 내보내기까지 막힘 없이 된다.

## 6. 작업 방식

`사용자 문제 하나 → 짧은 설계 → 끝까지 연결되는 작은 구현 → 테스트 → 실기기로 듣기 → 사용자 관찰 → 다음 우선순위`.
코드 테스트 통과와 "음악 앱으로 쓸 만한가"는 따로 확인한다.

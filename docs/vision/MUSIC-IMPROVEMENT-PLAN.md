# HumTrack 음악 기능 개선 계획

작성일: 2026-10-13 · 근거: [작곡과 프로듀싱 제품 검토](MUSIC-PRODUCT-REVIEW-2026-10-13.md) · 진행: [개발 체크리스트](music-checklist.md)

사용자의 멜로디를 보존하고 적합한 반주·전개·표현·내보내기를 연결한다. 우선 사용자는 취미 초보자이며, 전문 DAW 전체 재현보다 첫 곡 완성과 스스로 수정할 수 있는 경험에 집중한다.

## 기존 로드맵과 착수 순서

[VISION-ROADMAP.md](VISION-ROADMAP.md)는 단계와 완료 기준의 단일 기준이다. 이 계획의 M0~M3는 음악 개선 안의 우선순위이며, 별도 Phase나 기존 완료 기준의 교체가 아니다.

| 음악 우선순위 | 기존 단계 | 범위 | 착수 조건 |
|---|---|---|---|
| M0 결과 신뢰 | Phase 0, Phase 1 전 검증 | MIDI 스윙·효과 취소·반주 표시 | 현행 재현과 국소 수정 가능, 기존 안정화와 함께 처리 |
| M1 첫 창작 단순화 | Phase 1 | 흐름·추천 악기·후보 비교·웹 설명 | M0의 관련 결함 해결, 기존 guided 경로 기준 사용자 관찰 |
| M2 멜로디 보존 | Phase 2 | 평가 세트·원본·보정 선택·자유 수정 | Phase 1 관찰, 기준선 측정과 데이터 호환 설계 |
| M3 음악 완성과 전달 | Phase 3 | 화성·베이스·보이싱·강약·곡 전개·믹싱·전달 | M2의 관련 데이터 기반, 패키지별 검증 후 작은 단위 적용 |

당장 재현·설계·기준선 준비는 할 수 있다. 큰 기능 확장은 기존 단계 완료 조건에 따라 진행한다. 단조 표기·2마디 표기 등 사실과 결과의 일치는 M0에서 다루고, 멜로디 기반 반주 엔진 보강은 M3에서 다룬다.

2026-10-13에 확정된 [약속 Pro 기능 계획](PROMISED-FEATURES-PLAN.md)의 서버 권한·용량 검증, 우선 분석, 수동 백업·복원, 보컬 옵트인과 고지·출시 순서를 유지한다. M0의 작은 결함 수정은 병행 가능하지만 음악 개선 전체를 그 출시의 새로운 필수 조건으로 추가하지 않는다. 클라우드 일정과 음악 개선 일정이 충돌하면 작은 수정 단위와 담당 범위를 먼저 조정한다.

무료 공유는 기존대로 Phase 3에서 근거를 재확인하고 결정한다. 가격·Pro 범위·AI 정책·기본 피치 엔진은 이 문서로 변경하지 않는다. 기기 간 이어 하기는 약속 기능 계획의 이후 단계와 연결하며 별도 동기화 구현을 만들지 않는다.

| M0-02 | 효과 목록 삭제와 실제 오디오 일치 | 다중 효과 삭제 재현 | 보컬 편집·서버 FX | 부분 취소는 남은 체인과 소리 일치, 전체 초기화를 택하면 UI도 전체 취소로 명시, 원본 보존, 실패·취소 시 이전 오디오와 목록 유지 |

| M1-02 | 역할별 추천 음색과 공정한 반주 비교 | M0-03, 현행 악기·후보 흐름 | 음악 설계·UI/UX·웹 | 추천 세트 청취, 후보를 같은 구간·음색·음량으로 비교, 전체 악기·즐겨찾기 접근 유지, 웹은 출시 확인된 기능만 설명 |
| M2-01 | 허밍 평가 세트와 원본 데이터 계약 | Phase 2 평가 준비 | 음악 설계·분석·저장 | 튜닝/확인 세트 분리, 동의·로컬 보존·삭제 정책, 원본 피치·시각·길이와 보정 결과 구분, 구 저장 파일 호환 기준선 |
| M2-02 | 보정 선택과 화면 음역 독립 | M2-01 | 분석·모바일·UI/UX | 그대로/약한/그리드 보정 비교, 불확실 키 원본 유지, 화면 이동이 저장 음표를 바꾸지 않음, 기존 대비 오류·수정 횟수 평가 |
| M2-03 | 모든 음의 작은 수정과 자유 입력 | M2-01, M2-02 | 편집·UI/UX | 신뢰도와 무관하게 선택음의 피치·위치·길이 수정, 보정 해제, Undo·저장·복원·출력 일치 |
| M3-01 | 멜로디 기반 코드·베이스·보이싱 | M2-01, M0-03, 화음/꾸밈 역할 설계 | 음악 설계·반주·저장 | 긴 음·강박·마디 걸침·프레이즈 끝 평가, 코드와 베이스 연결, 잠금·수동 꾸밈 보존, 동일 음량 비교 평가 |
| M3-02 | 음표 강약과 미세 타이밍 | M2-01 데이터 계약 | 모델·오디오·내보내기 | 구 저장 파일 기본값 호환, 선택한 강약·타이밍이 재생·MIDI·WAV·스템에 같은 의미로 반영, 결정 가능한 프리셋 |
| M3-03 | 구간별 전개·변형·끝맺음 | M3-01, 강약 변화 사용 시 M3-02 | 편곡·구성 UI·재생 | 잠금 존중, 복제와 공유 반복의 차이 명확, 시작·변화·끝 또는 자유 구성, 전체곡 재생·출력에서 일치 |
| M3-04 | 기본 밸런스·솔로·스테레오 전달 | M0-01, M0-02, 채널 정책 | 오디오·믹서·출력 | 클리핑 방지, 레벨 맞춘 비교, 좌우 보존 검증, 믹스와 스템 재결합의 정렬·음량·꼬리 일관성 |
| M3-05 | 작은 창작 학습과 버전 비교 | M1 흐름, 해당 M3 기능 | UI/UX·저장·음악 설계 | 원본·수정본을 되돌리며 비교, 한 요소만 바꾸는 안내, 결과를 고정 취향 점수로 평가하지 않음 |

M3-01의 첫 구현은 고정 후보를 멜로디 적합성으로 평가하고 베이스를 화음에 연결하는 범위로 좁힌다. 고급 재화성·장르 확장·전문 화성 편집을 한 번에 만들지 않는다. M3-04도 솔로·음량·정확한 전달부터 시작하고 전문 믹서의 모든 기능을 묶지 않는다.

## 개발 설계에서 정할 사항

| 주제 | 권고 기본 방향 | 확인할 쟁점 |
|---|---|---|
| 보정 기본값 | 첫 허밍의 의도를 보존하고 비교 선택 | ‘그대로’의 피치·타이밍 의미, 키 불확실성 표시, 재녹음 부담 |
| 효과 취소 | 원본에서 남은 체인을 재처리 | 즉시 국소 수정이 필요하면 명확한 전체 초기화로 제한할 수 있음; 노드별 삭제인 것처럼 표시하지 않음 |
| 펜타토닉 | 연주용 음 집합과 화성 기준 구분 | 장·단조 기반 화음 또는 별도 화음 규칙 선택, 기존 곡의 소리를 임의 변경하지 않음 |
| 화음과 꾸밈 | 내부 역할·잠금·생성 대상 구분 | 기존 `melodyDec` 이전 방법, 사용자 수동 음표 보존, SongSpec 경계 |
| 강약·타이밍 | 원본/편집/재생 값을 구분 | 필드·단위·반올림·스윙 이중 적용 방지, MIDI 음색별 강약 반응 |
| 곡 전개 | 짧은 구조와 자유 구성 함께 지원 | 반복 공유와 독립 복제, 구간별 악기 활성·음량의 저장 의미 |
| 스테레오 | 모노 소스와 스테레오 출력 구분 | 샘플레이트·팬·공간효과·스템 헤드룸·개별 정규화 정책 |

이 설계 선택은 구현 명세에 기록한다. 새로운 비용·정책·핵심 기술 교체가 필요한 선택은 [지식 베이스 규칙](../knowledge/README.md)에 따라 최신 근거를 다시 확인한다. 그 밖의 가역적인 구현 선택마다 별도의 승인 절차를 추가하지 않는다.

## 평가와 완료 기록

기능 완료는 코드 검사, 파일/재생 일치, 실기기 청취, 대상 사용자 과제를 구분해 기록한다. 취향 차이를 자동 오류로 분류하지 않는다. 기준선과 목표를 정하기 전에 이미 개선됐다고 표시하지 않는다.

| 평가 | 기록할 항목 |
|---|---|
| 의도 보존 | 입력 대비 음정·옥타브·누락·분할·타이밍 오류, ‘내 멜로디 같다’ 응답, 수동 수정 횟수 |
| 반주 적합성 | 지속음·강박·베이스 관계·음역 경쟁·끝맺음, 음악가와 초보자 각각의 선택과 이유 |
| 통제 가능성 | 원하는 음·구간 수정 성공, 되돌리기·원본 비교·저장 복원 성공 |
| 첫 곡 | 기존 Phase 1 과제·3분 저장·이탈 단계, 저장과 음악적 전개의 평가를 분리 |
| 완성과 재사용 | 의도적인 변화·끝맺음, 동일 버전/플랫폼 코호트의 두 번째 곡 비율 |
| 전달 | 음표 타이밍·강약·구간 정렬·채널·스템 재결합·누락 파일·출력 꼬리 |

평가 세트는 장조·단조·불확실한 키·반음·반복음·긴 음·마디를 넘는 음·넓은 도약·쉼·엇박을 포함한다. 오디오 수집·보존은 기존 동의·정책을 따르고 서버 분석 파일을 임의로 저장하지 않는다. 기존 이벤트 수집·동의·출시 게이트를 유지하며 음성·음표·곡 제목을 분석 이벤트에 새로 넣지 않는다.

작업 완료 기록에는 ID, 커밋, 기준선과 결과, 대상 버전·플랫폼, 자동 검증, 청취·관찰 결과, 남은 한계를 남긴다. 체크리스트의 항목은 해당 증거가 있을 때만 체크한다.

## 이후 검토 범위

가사 메모, 다양한 박자, 고급 화성·악보, 전문 마스터링, 플러그인 호스팅, 실시간 공동 편집은 사용 수요가 확인될 때 검토한다. AI 편곡은 [기존 AI 로드맵](../AI_ARRANGEMENT_ROADMAP.md)의 내부 실험과 출시 조건을 따른다. 소비자용 웹 DAW는 현재 SoundLab과 구분해 별도 범위로 결정한다.

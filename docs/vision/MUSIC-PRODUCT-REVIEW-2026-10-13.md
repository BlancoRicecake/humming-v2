# HumTrack 작곡과 프로듀싱 관점 제품 검토

작성일: 2026-10-13 · 검토 소스: `a6db6ed`, 앱 `1.0.13+43`

HumTrack의 핵심 개선 과제는 사용자가 떠올린 멜로디를 보존하고, 작은 선택으로 전개가 있는 곡을 완성하게 하는 것이다. 허밍 입력·편집·반주·녹음·내보내기의 기반은 있지만, 의도 보존·반주 적합성·곡 전개·작업 전달 사이에 빈틈이 있다.

우선 대상은 기존 비전대로 취미 초보자다. 입문자에게는 자동 결과를 자기 선택으로 바꾸는 경험을, 중수·고수에게는 충실한 아이디어 포착과 다른 DAW로의 전달을 제공한다.

이 검토는 코드와 기존 테스트·문서에 근거한다. 코드에 기능이 있다는 사실은 스토어 제공·실기기 동작·청취 품질을 입증하지 않는다. 아래의 음악적 영향은 청취와 사용자 관찰로 검증할 가설이며, 구조적 결함은 재현 후 수정한다.

연결 문서: [제품 비전](VISION-ROADMAP.md), [개선 계획](MUSIC-IMPROVEMENT-PLAN.md), [개발 체크리스트](music-checklist.md), [결정 기록](context-notes.md).

## 역량 영역과 사용자 단계

| 영역 | 핵심 질문 | 필요한 역량 |
|---|---|---|
| 창작 | 무엇을 표현하고 싶은가 | 아이디어 포착, 취향 판단, 실험, 선택, 수정, 완성 |
| 작곡 | 어떤 음과 리듬으로 표현할 것인가 | 멜로디, 리듬, 화성, 동기 발전, 곡의 구조 |
| 편곡 | 어떤 악기가 언제 무엇을 연주할 것인가 | 악기 역할, 음역, 보이싱, 그루브, 밀도, 전환 |
| 프로듀싱 | 어떤 소리와 경험으로 완성할 것인가 | 방향 설정, 음색, 녹음·연주 판단, 편집, 믹싱, 결과물 관리 |

프로듀싱은 효과 처리뿐 아니라 연주 선택, 악기 생략, 강조 위치 등 곡 전체의 판단을 포함한다. Berklee도 청취·화성·녹음·보컬 제작·믹싱·마스터링을 연결해 가르친다. [Berklee 음악 프로덕션 교육과정](https://online.berklee.edu/music-degrees/undergraduate/music-production)

아래 단계는 제품 설계를 위한 기준이다. 공식 등급이나 미적 우열이 아니다. 장비 수, 복잡한 화성, 경력 연수 대신 스스로 결정하고 수정할 수 있는 작업으로 구분한다. 같은 사람도 영역마다 단계가 다르므로 앱에서 사용자를 고정 등급으로 분류하지 않는다. 사용자 화면에는 ‘하수’ 대신 ‘입문’ 등 중립적인 표현을 쓴다.

| 단계 | 창작과 작곡 | 편곡과 프로듀싱 | 관찰할 행동 |
|---|---|---|---|
| 초보자 | 짧은 아이디어를 떠올리고 결과를 듣고 선택 | 악기·반주·속도 차이를 감각적으로 선택 | 허밍 → 반주 선택 → 저장 |
| 하수 또는 입문자 | 음높이·길이·리듬 수정, 기본 코드·키·마디 이해 | 악기 역할 구분, 음량 조절, 반복 일부 변경 | 어색한 음이나 박자를 고치고 다른 구간을 연결 |
| 중수 | 멜로디 발전, 화성과 구간 대비 설계 | 보이싱·그루브·강약·음역·공간 조절, 원인 진단 | 지루함·충돌의 원인을 설명하고 해결 |
| 고수 | 장르와 목적에 맞는 구조, 관습의 의도적 활용·변형 | 방향·연주·소리·협업·납품 품질 관리 | 조건이 바뀌어도 방향을 유지하고 결과 재현 |

| 역량 | 초보자 | 입문자 | 중수 | 고수 |
|---|---|---|---|---|
| 멜로디 | 떠오른 가락 기록 | 음높이·길이·쉼표 수정 | 반복·변형·대조 | 정체성과 긴 흐름 설계 |
| 화성 | 어울리는 반주 선택 | 기본 진행 변경 | 전위·텐션·비화성음·재화성 | 스타일에 맞는 긴장과 해소 |
| 리듬 | 비트에 맞춰 듣고 입력 | 패턴·엇박·스윙 | 악기별 타이밍·강약 | 장르별 그루브 설계·변형 |
| 곡 구성 | 짧은 결과 완성 | 다른 구간 연결 | 밀도·전환·클라이맥스 | 목적에 맞는 전개와 길이 |
| 소리와 녹음 | 음색 선택·녹음 | 음량·트림·기본 효과 | 연주·음색·녹음 문제 구분 | 필요한 소리 제작·지휘 |
| 청취와 수정 | 선호 판단 | 문제 위치 찾기 | 원인 진단·비교 수정 | 전체 방향과 우선순위 유지 |

## 멜로디 의도 보존

새 곡 기본값은 A minor·92 BPM·2마디다. 직접 허밍 경로는 자동 키 탐지를 끄고 현재 키에 대한 적극 보정과 16분음표 그리드 정렬을 적용한다. 피치는 현재 보이는 패드 음역으로 맞춘다. [기본값](../../mobile/lib/looptap/models/loop_models.dart), [허밍 변환과 음역 매핑](../../mobile/lib/looptap/screens/edit_screen.dart), [매핑 함수](../../mobile/lib/looptap/music/hum_map.dart)

다른 키의 멜로디, 의도적인 반음, 앞서거나 늦는 표현, 넓은 도약이 달라질 수 있다. 키 안의 음과 사용자가 의도한 음은 다른 판단이다. 짧은 허밍의 키는 불확실할 수 있어 자동 탐지만 켜는 것으로 해결되지 않는다.

개선 방향은 원본 오디오와 분석된 피치·타이밍을 보존하고, ‘그대로 / 조금 정리 / 박자에 맞춰 정리’를 비교하게 하는 것이다. 원본 허밍 청취, 분석된 원음정, 보정 결과를 구분한다. 현재 직접 허밍의 `sourceMidi`도 옥타브 이동을 거치며 원래 타이밍 전체를 보존하는 모델은 아니다.

낮은 분석 신뢰도만으로 수정 대상을 제한하지 않는다. 높은 피치 신뢰도는 창작 의도의 정확성을 보장하지 않는다. 사용자가 지목한 모든 음에 대해 작은 음정·위치·길이 수정과 되돌리기를 지원한다. [현재 멜로디 검토](../../mobile/lib/looptap/widgets/sheets/melody_review_sheet.dart)

## 코드와 베이스의 적합성

현재 코드는 고정 진행 후보를 사용하고 베이스는 마디에서 시작한 첫 멜로디 음을 참고한다. 코드와 베이스의 결정 기준이 분리되어 있으며, 강박·긴 음·이전 마디에서 이어진 음 전체를 평가하는 경로는 아니다. [반주 구현](../../mobile/lib/looptap/music/beginner_backing.dart)

예를 들어 C 장조의 F–A–C 화음 위에서 마디 첫 멜로디 음이 B라면 베이스도 B를 선택할 수 있다. 이 조합 자체를 금지할 이유는 없지만, 초보자 기본 반주에서는 긴장과 해소를 고려한 의도적 선택인지 평가해야 한다.

우선 규칙 기반으로 멜로디 음의 길이·강박·프레이즈 끝과 코드 적합성을 평가하고, 선택된 코드에 연결되는 베이스를 만든다. 보이싱은 공통음과 이동 거리·악기 음역을 고려한다. [Ableton 보이싱](https://learningmusic.ableton.com/advanced-topics/voicings.html)

펜타토닉 연주용 음 목록과 화음 생성 기준은 분리해야 한다. 현재는 5음 목록에서도 같은 인덱스 간격으로 화음을 만들고 7도수 진행을 나머지 연산으로 매핑한다. 이런 화음도 표현 수단이지만 일반 장·단조 코드와 같은 의미로 표기하면 혼동된다. 후보 로마숫자는 장조 형태로 고정되어 있고, 기본 2마디에서는 표시한 4개 진행 중 앞의 2개만 생성된다.

후보 설명은 생성 결과에서 도출한다. ‘긴장을 더한다’ 같은 설명은 그 음악적 특성이 실제로 다른 후보에만 사용한다. 같은 구간·음색·음량 조건으로 들어보고 선택하게 한다.

## 곡 전개와 표현

구간 복제와 반복만으로는 다음 구간을 어떻게 다르게 만들지 알기 어렵다. ‘시작을 간결하게 → 다음 구간을 풍성하게 → 자연스럽게 끝내기’ 같은 작은 곡 구성부터 지원한다. 구간 역할, 악기 추가·생략, 멜로디 끝부분 변형, 짧은 필인·쉼, 끝맺음을 제공하되 모든 음악을 벌스·후렴 구조로 강제하지 않는다. [Ableton 곡 구조](https://learningmusic.ableton.com/song-structure/song-structure.html)

자동 화음이 사용하는 `melodyDec`는 멜로디 꾸밈에도 쓰인다. 사용자에게 트랙을 더 노출하지 않아도 화음과 꾸밈의 역할·생성 대상·잠금 의미를 구분해야 수동 작업을 예상 밖으로 대체하지 않는다.

음표·드럼 모델에는 개별 강약과 미세 타이밍 값이 없다. 일반 MIDI 음표는 대부분 고정 강약을 사용하고 기타 스트럼에만 별도 변화가 있다. 악기별 강약·프레이즈 강조·연주 길이·타이밍을 내부적으로 지원하고, 초보자에게는 소수의 표현 선택으로 제공한다. 무작위 흔들림보다 악기·패턴에 맞는 변화를 먼저 설계한다. [음표 모델](../../mobile/lib/looptap/models/loop_models.dart), [MIDI 생성](../../mobile/lib/looptap/music/midi_export.dart), [Ableton 그루브](https://www.ableton.com/en/live-manual/12/using-grooves/)

## 표시와 소리와 파일의 일치

| 코드에서 확인한 점 | 영향과 검증 대상 | 처리 방향 |
|---|---|---|
| 일반 MIDI 내보내기가 `swing`을 전달하지 않음 | 앱과 다른 DAW의 타이밍 차이 | 호출부터 이벤트 생성까지 전달·비교 |
| 다중 보컬 효과에서 노드 하나를 삭제해도 오디오를 재처리하지 않음 | 목록에서 없어진 효과가 소리에 남을 수 있음 | 남은 체인을 원본에서 재처리하거나 명확한 전체 초기화 제공 |
| WAV·스템 렌더 경로가 좌우를 합친 모노 출력 | 스테레오 공간 보존 제한 | 현재 출력 특성 안내, 이후 스테레오 지원 |

근거: [MIDI 내보내기](../../mobile/lib/looptap/music/midi_export.dart), [내보내기 호출](../../mobile/lib/looptap/widgets/sheets/export_drawer.dart), [효과 삭제](../../mobile/lib/looptap/widgets/sheets/vocal_editor.dart), [WAV 출력](../../mobile/lib/looptap/music/wav_codec.dart), [WAV 렌더](../../mobile/lib/looptap/music/wav_export.dart).

모노가 초보자에게 부적합하다는 뜻은 아니다. 현재 보존 범위가 명확해야 한다. MIDI 음색은 외부 악기에서 달라질 수 있지만, 편집한 타이밍이 누락되는 문제와는 구분한다.

현재 반주 테스트는 원본 보존·범위·저장·후보 차이를 확인한다. 멜로디와 어울리는 반주를 입증하는 청취 평가는 별도로 필요하다. [반주 테스트](../../mobile/test/looptap/beginner_backing_test.dart)

## 축약할 조작과 유지할 기능

| 현재 개념 | 첫 화면의 축약 | 상세 기능 |
|---|---|---|
| 전체 악기 카탈로그 | 역할별 추천 6~10개를 초기 후보로 검토 | 전체 목록·분류·즐겨찾기 유지 |
| 여러 기본 트랙 | 멜로디·반주·리듬·목소리 중심 | 개별 트랙·추가 오디오 접근 유지 |
| 로마숫자 후보 | 듣기와 실제 차이 설명 | 코드명·로마숫자 상세 보기 |
| BPM | 속도 미리듣기·탭 템포 검토 | 숫자 입력 유지 |
| 키·음계 | 추천 비교·원본 유지 | 직접 선택·자유 입력 |
| 여러 효과 | 청취 검증된 소수 프리셋과 강도 | 개별 효과 상세 편집 |
| A·B·C 구간 | 선택적인 시작·변화·끝 역할 | 자유 이름·순서 유지 |
| WAV·MIDI·스템 | 들려주기·다른 앱에서 이어 하기 | 형식·범위 선택 |
| 여러 입력 진입점 | 흥얼거리기·녹음 가져오기·직접 연주 | 공통 검토·확정 흐름 |

분위기·속도·에너지는 같은 속성이 아니다. 단순한 조작이라도 무엇이 바뀌는지는 일관되게 설명한다. 원본 보존·비교 듣기·실행 취소·저장 상태·오류 복구는 숨기지 않는다.

## 대상별 필요성과 후순위

| 대상 | 우선 가치 | 보강할 기능 | 현재 후순위 |
|---|---|---|---|
| 초보자 | 내 아이디어로 첫 음악 | 원본 보존·적합한 반주·간단한 수정·짧은 완성 | 복잡한 화성·전문 믹서 |
| 입문자 | 결과를 스스로 변화 | 강약·타이밍·코드 수정·구간 변형·기본 믹싱 | 복잡한 라우팅·플러그인 |
| 중수 | 빠른 아이디어 발전 | 자유 입력·보이싱·표현·버전 비교·스템 전달 | 전문 DAW 전체 재현 |
| 고수 | 이동 중 포착과 전달 | 충실한 원본·MIDI·오디오·구간 정보·파일 관리 | 모든 제작·마스터링을 앱 안에서 완결 |

작사 지원은 필요가 관찰되면 가사 메모부터 검토한다. 전문 악보·오케스트레이션·복잡한 박자 변화·고급 마스터링·실시간 공동 편집은 현재 범위에서 후순위다. 긴 강의보다 ‘베이스를 빼고 들어보기’, ‘끝 두 음만 바꾸기’ 같은 맥락 안의 학습이 적합하다.

## 개선 순서와 평가

결과 신뢰 확보 → 멜로디 보존 → 반주 적합성 → 짧은 곡 전개 → 표현과 성장 → 작업 전달 확장을 음악 기능의 순서로 권고한다. 실제 착수는 [기존 단계와 약속 기능을 연결한 계획](MUSIC-IMPROVEMENT-PLAN.md)을 따른다. 클라우드·우선 분석 착수 결정과 무료 공유의 Phase 3 결정을 이 검토로 변경하지 않는다.

평가는 저장 횟수뿐 아니라 ‘내 멜로디 같다’, 반주의 적합성, 원하는 수정의 성공, 의도적인 전개와 끝, 재사용을 함께 본다. 장·단조·긴 음·마디를 넘는 음·반복음·반음·넓은 도약·엇박을 포함하고 기존·개선 반주는 동일 음량 조건에서 비교한다. 취향 차이를 오류로 취급하지 않고, 음악가와 초보자의 판단을 함께 기록한다.

# HumTrack: 아이디어에서 완성곡까지

작성: 2026-10-22 · 사용자 요청을 바탕으로 Codex / VS Code Claude 협업

## 제품 목표

메인 제품은 HumTrack이다. HumTrack Studio는 연구와 비교를 돕는 보조 결과물이다.
초보자가 복잡한 MIDI 지식 없이 허밍 또는 악기별 입력으로 아이디어를 남기고,
노트를 자유롭게 편집하고, 연주 표현과 효과를 적용하고, 편곡·믹스를 다듬어 한 곡을 내보낸다.
기능의 개수보다 이 흐름을 끊김 없이 완료하는 것을 우선한다.

기본 화면은 `입력 → 편집 → 사운드 → 곡 구성 → 마무리`로 설명한다.
세부 수치·라우팅은 펼쳐서 조절한다. 생성과 자동 보정은 원본을 보존하고,
적용 전 비교와 한 번의 실행 취소를 제공한다. 사용자 멜로디·타이밍·세기는 기본적으로 유지한다.

## 구현 순서와 완료 기준

### 1. 기타 연주 표현: 첫 수직 단위

사용자 우선 음색: **어쿠스틱 기타의 스트로크와 잔잔한 아르페지오** (2026-10-22 추가 답변).
첫 비교는 오프라인 나일론 기타로 하고, 스틸 기타 등 다른 어쿠스틱 음색은 별도로 검증한다.

선택한 기타 노트/화음을 `다운 스트로크 / 업 스트로크 / 아르페지오`로 변환한다.
줄별 시작 시각과 세기, 울림 길이를 실제 노트 데이터에 반영하고 수정·취소할 수 있어야 한다.
실시간 재생과 MIDI/WAV는 같은 연주 이벤트를 사용한다. 기존 자동 스트로크를 중복 적용하지 않는다.
원본 MIDI의 미세 타이밍은 명시적으로 변환할 때만 바꾼다.

- 표준 튜닝의 실제 줄 배정 또는 배정 불가 상태를 명시한다. 피치 순서만으로 실제 줄을 안다고 간주하지 않는다.
- 같은 줄 재타현은 이전 울림을 끊고 다른 줄의 울림은 유지한다. 임의의 MIDI 음을 조용히 옥타브 이동하거나 버리지 않는다.
- locked/muted 노트, 같은 피치의 다른 줄, 섹션 경계, 루프 정지, 선택 없는 적용, Undo/복사/저장 호환을 검증한다.
- 팜뮤트·하모닉스는 음원 지원 능력과 분리한다. 길이 축소나 GM 28/31 대체는 근사 표현으로 표시한다.
- 작은 자체 제작 8마디 진행으로 일반/스트로크/울림 아르페지오를 같은 음량에서 비교한다.

### 2. 효과의 공통 경로

기타 기반이 안정되면 트랙의 간단한 사운드 프리셋(EQ·압축·공간감), 이어서 노트별 효과를 제공한다.
보컬의 모노 오프라인 FX를 스테레오 악기 버스에 그대로 덧붙이지 않는다.

- 트랙 버스와 노트 음성의 처리 책임을 분리한다. 한 노트의 Pan/필터/딜레이가 겹쳐 연주하는 다른 노트에 새지 않는다.
- 기본 모드는 `따뜻하게 / 선명하게 / 넓게`처럼 목적 중심으로, 세부 체인은 펼쳐서 조절한다.
- 드라이 원본과 비파괴 파라미터를 보존하고 우회/삭제/순서 변경·Undo를 검증한다.
- 라이브·풀 믹스·스템의 처리 순서, FX tail, 트랙 Pan, 헤드룸을 일치시킨다.
- 일반 MIDI가 오디오 FX를 담지 못하면 명확히 알리고 WAV/스템에 반영한다.

### 3. 자동 프로듀싱

첫 버전은 설명 가능한 제안 방식이다. `편곡`과 `믹스`를 구분한다.
편곡은 잠그지 않은 파트만 후보를 만들고, 믹스는 트랙 레벨·Pan·공간감과 피크 여유를 제안한다.
프리셋 레벨은 실제 음량을 측정한 자동 믹싱으로 부르지 않는다.

- 사용자 멜로디와 잠근 트랙은 바꾸지 않는다. 후보 미리듣기 → 적용 → 한 번의 Undo.
- 인트로/벌스/후렴/마무리와 전환의 차이를 1곡 안에서 들을 수 있게 한다.
- 렌더한 파형의 피크·RMS/라우드니스와 저역 충돌을 측정한 후에만 측정 기반 균형 조정이라고 표시한다.
- 원본/결과 비교 시 지각 음량 차이로 품질을 오판하지 않도록 레벨을 맞춘다.
- 장르·악기별 결과는 주관 평가를 병행한다. 자동화가 상업용 마스터 품질을 보장한다고 주장하지 않는다.

### 4. 허밍부터 완성곡까지 통합

허밍 → 악기 지정 → 노트 수정 → 기타 표현 → 반주 후보 → 곡 구조 → 효과/믹스 → 내보내기.
각 단계에서 다음 행동을 바로 찾을 수 있게 하며 고급 도구를 기본 화면에 모두 노출하지 않는다.
제품 검증곡은 저작권 문제가 없는 자체 작곡으로 시작하고, 사용자 제공 MIDI는 별도 비교용으로 사용한다.

## 현실적인 기타 음원의 조건

스케줄링 개선과 음원 품질은 별개다. 현재 FreePats nylon/clean 음원과 GM mute/harmonics가 있으나
피킹 위치·다중 벨로시티·라운드로빈·릴리스 소음·실제 팜뮤트/하모닉스의 보유 여부는 자산별로 확인해야 한다.
지원하지 않는 샘플을 파라미터만 추가해 실제 녹음과 같다고 부르지 않는다.
우선 보유 음원으로 연주 표현을 검증하고, 부족한 아티큘레이션은 자체 녹음 또는 배포 가능한 별도 팩으로 보강한다.

공식 참고:
- [FreePats nylon guitar](https://freepats.zenvoid.org/Guitar/acoustic-guitar.html): 실제 기타 녹음·CC0, 제작자가 녹음 조건과 필터 처리를 설명한다. 고급 아티큘레이션 제공은 이 페이지로 확인되지 않는다.
- [MIDI CC 표](https://midi.org/midi-1-0-control-change-messages): CC7/CC10 등은 채널 제어다. 노트별 FX는 별도 음성/버스 설계가 필요하다.
- [Ableton MPE 설명](https://www.ableton.com/en/manual/editing-mpe/): 노트별 표현과 채널 전체 제어의 차이. MPE만으로 임의 오디오 FX 체인이 구현되는 것은 아니다.

## 협업과 변경 보존

- Claude: 모든 앱 코드·도구·테스트의 작성/수정, 합의한 기능 구현과 빌드.
- Codex: 작업 관리, 제품 문서·수용 기준, 독립 코드 검토와 프로그램 실행 검증. 사용자 역할 확정 후에는 코드나 테스트를 직접 수정하지 않는다.
- 같은 파일을 동시에 수정하지 않는다. 후속 구현은 최신 변경을 다시 읽고 이어간다.
- C:/src/humming-v2 밖에 새 프로젝트/임시 산출물을 만들지 않는다. 분석 격리 자료는 사용자의 지시대로 현재 위치에 유지하며 이번 구현에서 읽지 않는다.
- 기존 미커밋 파일을 되돌리거나 옛 소스를 덮지 않는다. 공개/배포·Git 커밋은 이번 요청에 포함하지 않는다.

# HumTrack: 곡 완성을 위한 기능 점검

2026-10-23 · Codex 관리·교차검토 / VS Code Claude 소스 감사

## 판단

현재 HumTrack에는 곡을 입력·편집하고 섹션을 이어 WAV로 내보내는 기본 골격이 있다. 짧은 루프만 만들 수 있는 상태는 아니다. 다만 **초보자가 의도한 소리로 한 곡을 마무리하는 흐름과 믹스 도구는 아직 부족하다.**

특히 자동 반주를 다시 적용하면 생성 잠금이 없는 베이스/화음/드럼 트랙 전체를 교체한다. 해당 트랙의 개별 노트 잠금은 별도로 보존하지 않는다. 실증에서는 트랙 생성 잠금으로 기존 파트를 보호하고, 자동 반주를 확대하기 전에 이 보호 규칙부터 보완해야 한다.

이번에는 현재 작업 트리의 코드·UI 연결점·기존 테스트를 읽고 점검했다. 앱/테스트 코드를 수정하거나 빌드하지 않았고, 사용자 곡도 편집하지 않았다. 이전 745개 테스트 통과를 허밍부터 2~3분 완성곡까지의 실증으로 간주하지 않는다. 이번 점검에서 실제 녹음·서버 변환·전체 곡 렌더·청취를 새로 수행하지 않았다.

Claude의 상세 감사: [claude-audit.md](C:/src/humming-v2/artifacts/song-completion-audit-20261023/claude-audit.md). 과거 계획과 기능 카탈로그는 구현 완료의 근거로 쓰지 않았다. HumTrack Studio는 이번 제품 평가 대상이 아니다.

## 이미 있는 기능과 남은 간극

| 단계 | 현재 기능 | 아직 부족한 것 |
|---|---|---|
| 아이디어 입력 | 허밍/보컬→MIDI, 악기 패드·키보드 연주·그리드·MIDI 가져오기 | 허밍 변환은 서버가 필요하다. 실제 목소리·마이크·지연 환경의 성공률을 측정한 완성곡 실증은 이번 자료에 없다. 오프라인 변환은 없다. |
| 노트 편집 | 선택·영역 선택·이동·길이·복사/붙여넣기·삭제·Undo, 원래 미세 타이밍/세기 보존, 양자화·휴머나이즈·그루브 | 악기 노트별 임의 오디오 FX는 없다. 드럼의 복사/붙여넣기 경로도 피치 노트와 동등하지 않다. |
| 기타 표현 | 다운/업·패턴 스트로크, 줄 배정, 아르페지오 울림·줄별 울림 유지, 짧게·팜뮤트/하모닉스 근사 | 실제 어쿠스틱 팜뮤트·하모닉스 전용 샘플과 연속 연주의 사실감은 별개다. 현재 GM 대체 음색을 실제 녹음과 동등하다고 판단하지 않는다. |
| 반주 | 분위기 3종·후보 비교·적용·Undo·생성 잠금 | 가이드 모드의 활성 섹션에만 적용된다. 사용자 코드 진행을 공유하는 반주 체계와 곡 전체 적용은 없다. 베이스는 멜로디 첫 음, 화음은 고정 진행을 참고한다. 전위·경과음은 정상적인 표현이므로 근음 차이 자체를 오류로 단정하지 않는다. |
| 곡 구성 | 섹션 추가·이름·복제·연결 복제·순서·반복·곡 전체 재생 | 긴 곡은 이미 만들 수 있다. 다만 인트로/벌스/후렴/아웃트로를 빠르게 구성하고 밀도·전환을 제안하는 흐름은 없다. 일반 마디 UI는 1/2/4마디여서 큰 단위 편집이 번거롭다. |
| 보컬 | 녹음·여러 클립·자르기·페이드·게인·원복, 로컬 FX 10종과 프리셋 8종, 음량 맞춘 A/B | EQ·리버브·컴프 등 일부 효과와 오토튠은 서버 의존이다. **곡 전체를 한 번에 녹음한 테이크는 섹션 클립 편집/FX 흐름과 연결되지 않는다.** 템포 변경에 맞춘 자동 오디오 워프/다중 테이크 컴핑도 없다. |
| 믹스 | 트랙 볼륨·Pan·Mute·Solo, 신스 전역 리버브와 고정 출력 보호 | 악기 트랙별 EQ/컴프/리버브 체인, 조절 가능한 마스터·레벨 미터·측정 기반 자동 밸런스가 없다. 보컬 FX가 있다는 이유로 악기 FX도 있다고 볼 수 없다. |
| 시간에 따른 변화 | 노트 세기·길이, 보컬 클립 게인·페이드 | 트랙 볼륨/Pan/FX 오토메이션은 없다. 곡 끝 전체 페이드나 후렴에서 특정 악기만 서서히 키우기 어렵다. 보컬 페이드가 전혀 없는 상태는 아니다. |
| 저장·이동 | 12초 자동 저장·원자적 저장·이전 .bak·손상 보존·스키마 보호 | 보컬 원본·사용 음원 참조를 묶는 프로젝트 내보내기/복원 UI는 없다. 로컬 복구와 기기 간 프로젝트 이식은 다르다. 미디어 누락/음원 대체 안내도 보강 대상이다. |
| 결과물 | 스테레오 44.1kHz/16bit WAV·스템·MIDI, 파일 저장/공유 | 출력은 Pro 게이트가 있다. 이는 기능 부재와 다르며 이번 점검에서 정책을 바꾸거나 우회하지 않았다. 출력 직전 소리/미디어/음량을 종합 확인하는 마무리 과정은 부족하다. |

## 우선순위

| 순서 | 과제 | 곡 제작에서 달라지는 점 | 판단 |
|---|---|---|---|
| 0 | **현재 기능으로 자작곡 1곡 완성 실증** | 입력→편곡→보컬→저장/재열기→WAV를 실제로 연결하고 막힌 단계·걸린 시간을 남긴다. | 가장 먼저 할 검증. 새로운 노래 분석기를 만들지 않는다. |
| 선행 수정 | **반주 재적용 시 기존 파트·개별 잠금 보호** | 사용자 아이디어를 반주 생성이 조용히 덮어쓰는 상황을 막는다. | 자동 반주 확장보다 먼저. 빈 트랙 우선·명시적 교체·잠금 보존 규칙이 필요하다. |
| 1 | **마무리 출력의 신뢰성** | 누락 보컬·다른 음원 대체를 알리고, 들으며 맞춘 밸런스와 WAV 결과의 차이를 확인한다. | 기능 확장 전 기준을 세운다. 출력 경로 차이 자체와 청취상 문제를 구분한다. |
| 2 | **악기 트랙 기본 사운드** | 기타의 톤·공간감, 베이스/드럼의 정리 등을 트랙별로 조절한다. | 다음 핵심 기능 후보. 원본/우회/Undo와 재생·WAV·스템 일관성을 포함해야 한다. |
| 3 | **구간별 음량 변화와 보컬 편집 연결** | 후렴의 크기 변화·아웃트로 페이드, 곡 전체 보컬 테이크에 효과 적용이 가능해진다. | 단순한 구간 게인/페이드부터. 복잡한 전체 오토메이션 편집기는 나중에 확장한다. |
| 4 | **곡 전체 반주·구성 보조** | 매 섹션마다 같은 작업을 반복하는 부담을 줄이고 곡의 역할·전환을 찾기 쉬워진다. | 기존 반주/섹션 재사용. 자동 생성은 기존 파트를 기본 보호하고 빈 트랙을 우선한다. |
| 5 | **휴대 가능한 프로젝트 보관** | 다른 PC/기기로 곡·보컬·음원 참조를 함께 옮겨 이어 작업한다. | 로컬 .bak을 대체하는 기능이 아니다. 누락 탐지와 재연결도 필요하다. |

진짜 어쿠스틱 기타 표현을 더 높이는 일도 중요하지만, 현재 스트로크/울림 기반을 이미 갖췄으므로 전용 샘플과 연주 결과의 청취 평가로 다음 보강을 정한다. VST/AU 호스팅·다양한 박자표·템포 맵·하드웨어 MIDI·기기 안 허밍 분석기를 첫 완성곡의 필수 선행 조건으로 삼지 않는다.

## 다음 작업 단위 제안

**먼저 아래 자작곡 실증을 한 번 진행하고, 확인된 출력 누락/밸런스 문제를 작은 범위로 정리한다. 다음 사용자 기능은 악기 트랙의 기본 사운드 조절을 우선 검토한다.**

출력 점검은 기존 렌더를 이용한 확인 작업이다. 별도 곡 분석 서비스나 자동 프로듀싱 엔진을 만드는 작업으로 확대하지 않는다. 일반 미터나 최종 WAV 미리듣기 화면을 붙인다면 실제 사용자가 판단할 수 있는 결과를 보여준다.

악기 사운드의 첫 구현 범위는 기타 한 트랙의 공간감/톤부터 시작할 수 있다. 다음 조건이 필요하다.

1. 효과 없는 원본과 비교, 우회·초기화·Undo, 저장/재열기를 지원한다.
2. 기타 트랙의 처리가 다른 트랙이나 겹쳐 울리는 음에 새지 않는다.
3. 재생·최종 WAV·스템에 같은 설정과 의도한 처리 순서가 반영된다. MIDI가 담을 수 없는 오디오 처리는 구분한다.
4. 리버브 꼬리가 잘리지 않고, 볼륨/Pan과의 순서를 명시한다.
5. 신스 CC를 보낸다는 이유만으로 모든 플랫폼이 똑같이 지원한다고 가정하지 않는다. 실시간/렌더 엔진의 지원을 먼저 검증한다.

임의의 노트별 독립 FX는 트랙 효과 다음으로 둔다. 현재 기타 연주법별 채널 배정은 임의 FX를 노트마다 독립 처리하는 엔진과 다르다. 보컬의 모노 파일 FX를 스테레오 악기 신스에 그대로 붙여도 해결되지 않는다.

## 완성곡 실증 시나리오 (아직 실행하지 않음)

100 BPM, 4/4, 자체 작곡 64마디: 인트로4 + 벌스16 + 후렴16 + 브레이크8 + 후렴16 + 아웃트로4. 음악 구간은 153.6초(2분33.6초)이며 현재 4마디 섹션과 반복으로 구성할 수 있다.

1. 허밍으로 벌스/후렴 아이디어를 입력하고 틀린 음을 고친다. 서버 연결, 실패/재시도, 녹음 장치를 기록한다. 직접 그리드 입력 경로도 확인한다.
2. 나일론 기타·베이스·드럼을 배치하고, 기타 스트로크/울림을 적용한다. 반주 생성 전 사용자 파트를 복제하거나 잠가 보호한다. **현재 반주 함수는 트랙 생성 잠금만 확인하고 해당 트랙 전체를 교체하므로, 개별 노트 잠금만으로 보호된다고 믿으면 안 된다.**
3. 연결 복제와 반복으로 구조를 만들고, 후렴 앞 필과 파트의 유무를 직접 조정한다.
4. 보컬이 필요하면 먼저 기존 섹션 클립 편집/FX 경로로 진행하고, 통곡 테이크 편집의 빈틈은 별도로 기록한다.
5. 볼륨·Pan·Solo로 정리하고 곡 전체를 듣는다. 기타 사실감·보컬 정렬·화성·믹스 균형은 사람이 판단한다.
6. 저장→정상 종료→재실행. 노트/섹션/악기/설정과 보컬 참조가 보존되는지 확인한다.
7. 정당한 Pro 권한으로 WAV·스템·MIDI를 출력한다. 사용자에게 계정/구독 처리가 필요한 경우 별도 사용자 작업으로 남긴다.

합격·비교 기준:

- 음악 데이터는 저장 전후 동일해야 한다. updatedAt·재생 상태 같은 비음악 메타데이터를 제외하고 비교한다.
- 누락 보컬 0, 의도하지 않은 음원 대체 0. 조용히 빠진 트랙이 없어야 한다.
- 길이는 렌더 스케줄과 일치하고 마지막 음의 꼬리를 보존한다. 현재 WAV 렌더의 기본 tail은 1.2초이며 실제 파형과 무음 끝을 함께 확인한다.
- PCM 피크·무음·클리핑을 측정한다. 현재 피크 목표0.94는 16bit 양자화 1LSB 오차를 허용한다. 이 수치만으로 라우드니스/마스터링 품질을 통과 처리하지 않는다.
- 스템별 감쇠와 믹스 정규화가 다르므로, 완성 스템을 더해 단일 게인만 맞추면 WAV와 항상 같아진다고 요구하지 않는다. 정규화 전 합산 경로 또는 기록된 각 경로의 게인을 기준으로 비교한다.
- 이벤트 시각의 일치와 실제 기기의 지연·드리프트를 구분한다. 코드상 같은 이벤트를 쓴다는 이유로 실제 오디오 캡처가 샘플 단위로 같다고 주장하지 않는다.
- 최종 파일을 실제로 다시 듣고, 악기 균형·보컬 정렬·전환·엔딩을 평가한다. Windows 데스크톱과 모바일 실기기의 결과를 구분한다.

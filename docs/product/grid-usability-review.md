# 그리드 사용성 개선 리뷰

2026-10-23 · 사용자 요청 · Claude 코드/테스트/빌드, Codex 관리/리뷰/독립검증/화면 확인

## 문제와 목표

사용자는 음과 시간의 구분이 어렵다고 피드백하고, 편집 영역 확대·마디/박자 눈금·피아노 건반·선택 구분을 요청했다.
1266×714 기존 창에서 실제 피치 그리드는 약 100px로 네 음줄 정도만 보였다.
타임라인과 여러 도구/세기 행에 비해 노트 공간이 좁았고, 시간 기준·작은 음이름·선택 표현을 파악하기 어려웠다.
최대화하면 음줄은 늘지만 눈금/건반/선택의 표현 문제는 남았다.

## 수용 기준

- 그리드 모드는 노트 편집 공간을 우선한다. 작은 창에서도 확대/타임라인 접기와 보조 도구 접기가 쉽게 보인다.
- 노트 바로 위 마디·박자 눈금, 서로 구분되는 마디/박/세부선. 긴 곡·좁은 폭에서도 글자가 겹치지 않는다.
- 건반·음이름/옥타브는 실제 음줄과 맞고 세로 스크롤을 함께 따른다.
- 일반 노트와 선택 노트는 서로 다른 색과 비색상 표시로 구분한다. 짧은 노트·다중 선택·잠김/뮤트·기타 표시를 보존한다.
- 시간 눈금·그리드·velocity·playhead·히트 테스트는 같은 gutter/시간 좌표를 사용한다.
- 입력·선택·영역 선택·이동/길이 수정·복사/붙여넣기·Undo/Redo 동작과 원래 미세 타이밍/세기·G0–G4 데이터를 보존한다.
- 작은 데스크톱 창과 최대화 화면을 Codex가 직접 확인한다. 모바일의 기존 편집 경로도 스모크 테스트한다.

## 단축키 추가 검증

- 실제 포커스 키 이벤트로 확인한 영문 Ctrl/Cmd+Z 및 Redo는 기존 소스에서도 통과했다. 따라서 1차 네이티브 관찰의 원인이 포커스 또는 IME라고 아직 확정하지 않았다.

# 앱·데스크톱 원격 공지 MVP — 구현 지시 (2026-10-30)

## 사용자 목적과 현재 근거
앱을 켤 때 개발 소식·장애·긴급 오류를 사용자에게 전달하고, 나중에 다시 읽을 수 있게 한다. 현재 policy_notice.dart는 약관 개정 전용 고정 배너, library_notice.dart는 기기 저장 문제용이다. 일반 원격 공지는 없다. 기존 두 안내를 대체하거나 삭제하지 않는다.

대상은 mobile/의 같은 Flutter 앱으로 나가는 Android/iOS 및 Windows/macOS다. 별도 Electron Studio는 같은 공지 형식을 재사용할 수 있게 문서화하되 이번에 소스를 임의로 바꾸지 않는다.

## 운영 방식 (첫 버전의 범위)
- 최초 한 번 공지 기능이 포함된 앱/프로그램을 배포해야 한다. 그 뒤에는 공지 내용만 원격에서 바꾸며 앱 재배포가 필요 없어야 한다.
- 공지 원본은 Supabase의 전용 app_announcements 테이블. 처음에는 운영자가 Supabase 대시보드에서 초안 작성·검토·게시·수정·회수를 한다. 별도 관리자 웹 앱은 후속이며, 이번에 계정/관리자 인증 체계를 새로 만들지 않는다.
- 앱은 공개된 공지만 익명 읽기. 무료/Pro·로그인 여부와 무관. 앱 안에서 작성·수정하는 권한/관리자 키를 넣지 않는다.
- 분석/클라우드 백업 서버가 중단돼도 공지를 읽도록, 공지 읽기는 같은 Supabase 공개 REST 피드를 직접 사용하고 엔진 API에 종속시키지 않는다. 설정이 없는 로컬 빌드는 조용히 기능을 끈다.
- 기존 SUPABASE_URL/공개 anon key 설정을 재사용한다. service_role·새 비밀키를 클라이언트에 넣지 않는다. 토큰·서명 URL·공지 본문을 로그로 남기지 않는다.
- 운영 DB 마이그레이션·실제 게시·고객 메시지 전송·배포는 이번에 하지 않는다. 샘플은 테스트 fixture/초안으로만 둔다.

## UI/UX
1. 공지 센터: 홈의 작은 공지 진입점과 설정의 '공지사항'. 읽은 것도 목록에서 다시 연다. 새 공지는 읽지 않음 표시. 한국어/영어.
2. 일반/중요 공지: 곡 목록 홈에 대표 배너 하나(필요 시 개수+목록 링크)로 표시. 여러 팝업을 연속해서 띄우지 않는다.
3. 긴급 공지: 앱 시작 뒤 곡 목록 홈이 준비되고 다른 모달/녹음·카운트인이 없을 때, 해당 id+revision에 대해 확인할 때까지 다음 안전한 실행 시 한 번 보여 준다. 같은 실행에서 무한 재표시하지 않는다. 사용자가 '확인'하면 이 기기에 저장하고 같은 revision 팝업은 반복하지 않는다. 닫기/나중에는 확인 처리와 구별한다.
4. 편집·재생·녹음 중 갑자기 모달을 띄우거나 작업을 막지 않는다. 재개 시 새 공지는 읽되 다음 안전한 홈에서 안내한다. 기존 재생·저장·모달 동작을 바꾸지 않는다.
5. 긴급 공지도 설정 목록에서 다시 열 수 있다. 게시 회수·종료 기간이 지난 공지는 배너·팝업에서 제거한다. 기존 약관 고지의 별도 확인 상태는 유지.
6. 본문은 일반 텍스트. HTML/스크립트/명령 실행 없음. 링크는 사용자가 누를 때만 열고, 지원한 https 도메인/고정 문의 메일 등 안전한 action만 허용한다. 원격 값으로 기기 파일 경로나 임의 URI를 열지 않는다.

## 데이터 계약과 로컬 처리
- 고유 id, revision, 종류(info/important/critical), KO/EN 제목·본문, 게시 여부(기본 false), 게시 시작/종료 시각, 대상 플랫폼 배열, 선택적 최소/최대 빌드 번호, 선택적 action.
- 운영자가 수정할 때 revision 갱신이 실수로 누락되지 않도록 DB trigger 또는 동등한 명확한 장치를 둔다. 새로운 revision은 새 공지로 판단한다.
- 날짜는 UTC. 불가능한 기간, 알 수 없는 종류, 잘못된/너무 큰 내용은 거부·무시하되 다른 정상 공지는 계속 처리한다. 최대 항목 수/본문 길이/응답 크기 제한을 둔다.
- RLS로 anon/authenticated 모두 '게시됨 + 활성 기간'만 읽게 한다. draft/미래 예약 공지를 REST로 미리 조회할 수 없고, anon/authenticated 쓰기/RPC 우회도 차단한다. 플랫폼·빌드 대상은 클라이언트에서도 검사한다.
- 앱 시작을 네트워크 응답으로 막지 않는다. 짧은 제한 시간과 백그라운드 갱신, 앱 재개 시 적절한 갱신 간격을 둔다. 새로 설치하거나 오프라인이어도 곡 목록이 바로 열린다.
- 마지막 정상 캐시만 사용하고, 만료된 캐시는 숨기거나 오래된 자료임을 명확히 표시한다. 성공한 빈 응답은 회수로 반영한다. 실패/손상 응답으로 정상 캐시나 확인 기록을 덮어쓰지 않는다.
- 캐시와 확인 기록은 저장소 안의 실제 원자적 저장 경로로 검증한다. 병렬 갱신/중복 이벤트와 Windows의 일시적 rename 거부에도 기존 기록 보존. 최근 클라우드 검증에서 찾은 같은 문제를 반복하지 않는다.

## 구현·검증 요구
- 현재 C:/src/humming-v2 미커밋 파일이 최신이다. 기존 저장/클라우드 수정, changelogs 삭제 표시, landing 등 다른 변경을 보존한다. 브랜치 전환·병합·commit·push·PR 금지.
- SQL은 다음 번호의 마이그레이션으로 추가하고 운영에는 적용하지 않는다. 실제 로컬 PostgreSQL로 공개 읽기/초안 비노출/클라이언트 쓰기 차단/예약·만료를 확인한다.
- 테스트는 fixture만 사용. 최초 표시/확인 후 재실행/수정 revision 재표시/일반 공지 과도한 팝업 없음/빈 feed 회수/오프라인·캐시 손상/기간·플랫폼·빌드/잘못된 링크/중복 요청을 검증한다.
- 320px 확대 글꼴·휴대폰 가로·960px 데스크톱에서 제목·본문·버튼 접근 가능, 긴 본문은 스크롤. 큰 시스템 글꼴도 확인한다.
- Flutter analyze 및 관련/전체 테스트, 현재 mobile/에서 Windows 제품 빌드. mobile/build 재사용. artifacts/releases/current 및 기존 검증 앱을 바꾸지 않는다.
- 결과는 docs/specs/announcements/announcements-mvp-2026-10-30.md와 artifacts/announcements-2026-10-30/ 아래에 저장한다. 운영자 게시 가이드(초안→미리 확인→게시→수정→회수, 플랫폼/기간/빌드 번호)와 미확인도 남긴다.
- 앱 자체가 실행되지 않는 장애에는 인앱 공지만으로 전달할 수 없다는 한계도 운영 가이드에 명시한다. 외부 홈페이지 공지/푸시는 별도이며 이번에 실제 공지나 메일은 보내지 않는다.

# 공지 이미지 지원 — 2026-11-04

앱(Flutter)·웹 공지에 선택형 이미지 1장을 추가했다. 기존 제목·본문·버튼과
게시/기간/대상/RLS 정책을 유지한다. **로컬 구현이며 운영 DB 적용·배포·공지 게시를 하지 않았다.**

## 작성과 표시

- 관리자 `/admin/notices`: 이미지 주소와 한국어·영어 이미지 설명을 입력한다.
  선택 항목이며, 이미지를 쓰면 두 언어 설명이 모두 필요하다. 미리보기 언어를 바꿀 수 있다.
- 이미지 주소는 `https://hum-track.com/assets/notices/<파일명>.png` 형식이다.
  `www` 호스트, `.jpg`·`.jpeg`·`.webp`도 허용한다. 파일명은 영문·숫자·하이픈·밑줄만 사용한다.
  쿼리·SVG·외부 도메인·포트·사용자 정보·상대 경로는 허용하지 않는다.
- 파일은 관리자가 `landing/assets/notices/`에 준비해 사이트와 함께 배포한다.
  관리자 폼에서 직접 파일을 업로드하는 기능은 이번 범위에 포함되지 않는다.
- 이미지 URL 최대 512자, 설명은 언어별 최대 300자.
- 제목/날짜 아래, 본문 위에 표시한다. 전체 이미지를 contain으로 보여 잘라내지 않는다.
- 앱 상세와 긴급 팝업, 공개 웹 상세와 관리자 미리보기에 표시한다.
  목록/홈 배너에는 기존처럼 제목을 표시한다.
- 이미지가 없으면 기존 텍스트 화면이다. 잘못된 이미지 메타데이터는 그림만 생략한다.
  다운로드 실패 시 안내와 본문을 표시한다. 읽음·확인 버튼은 계속 사용할 수 있다.
- 한·영 설명은 스크린리더의 대체 텍스트로 사용한다. 웹은 referrer를 보내지 않는다.
  앱도 이미지 요청에 계정 토큰/anon key를 붙이지 않는다.
- 공지 JSON 캐시는 이미지 주소와 설명도 보존한다. 이미지 파일 자체를 디스크에
  오프라인 저장하는 기능은 추가하지 않았다. 오프라인에 그림이 없으면 본문을 읽을 수 있다.

## DB와 호환성

`backend/migrations/009_announcement_images.sql`은 `005`와 관리자 `006` 이후 적용한다.
`image_url`, `image_alt_ko`, `image_alt_en`을 nullable로 추가한다. 셋 모두 비우거나 모두 채운다.
이미지/설명 수정과 제거도 revision을 올린다. 따라서 기존 정책처럼 다시 읽지 않음으로
표시하고, 긴급 공지는 재확인 대상이 된다. 기간·대상·게시 상태 변경은 revision을 유지한다.
마이그레이션 재실행을 검증했다. 기존 행에 이미지를 넣거나 게시하는 SQL은 없다.

앱/웹 피드는 `select=*`로 읽고 모르는 필드를 무시한다. 새 컬럼이 없는 기존 DB에서도
텍스트 피드를 계속 읽을 수 있다. 공지 테이블의 published/기간 RLS와 앱의 응답 크기 제한은 유지한다.
기존 클라이언트도 새 필드를 무시하고 텍스트를 표시할 수 있다.
관리자에서 이미지 저장은 009 적용 후 사용한다. 미적용 오류는 입력 내용을 보존하고 안내한다.
**009 이후에 옛 005만 단독 재실행하면 이미지가 빠진 옛 revision 함수로 바뀔 수 있으므로
새 설치/복구는 005 → 006_announcements_admin → 009 순서로 수행한다.**

## 실제 적용 순서 — 아직 수행하지 않음

1. 운영 DB의 기존 공지/정책을 확인하고 009 마이그레이션 적용.
2. 이미지 자산과 웹 관리자/공개 페이지 배포. 실제 이미지 URL 응답 확인.
3. 이미지 지원 앱을 빌드·내부 검증 후 배포. 구버전은 텍스트로 표시됨.
4. 승인된 공지를 `published=false`로 저장해 비공개와 미리보기 확인.
5. 사용자가 실제 게시를 요청할 때 시작 시각/대상을 확인하고 공개.

승인된 공지 자료: `artifacts/announcements/2026-11-04-community-feedback/`.

초안 저장은 사용자 확인으로 남겼다. [사이트 배포 기록](../../release/SITE-DEPLOY-2026-11-03.md).

운영 반영 상태: 11/02 사용자 승인으로 공지005·관리자006과 운영 Redirect URL을 적용했다.
확인 결과 true/true/2/0, 공개 피드 HTTP200·0건, 관리자 목록 공개 조회401.
웹 배포·공지 게시는 하지 않았다. [실제 적용 기록](../../release/ANNOUNCEMENTS-PRODUCTION-2026-11-02.md).

공지는 하나의 표(`app_announcements`)에서 나온다. 앱, 웹 공지 페이지, 관리자 페이지가 모두 같은 행을 읽는다.

| 화면 | 주소 | 누가 |
|---|---|---|
| 공개 공지 페이지 | `hum-track.com/notices`, 한 건은 `#공지id` | 누구나. 게시 중인 공지만 보인다 (005의 읽기 규칙). |
| 관리자 페이지 | `hum-track.com/admin/notices` | `app_admins`에 있는 이메일만 (처음엔 `humtrack@gmail.com`). Google 로그인. |
| 앱 | 공지 목록의 ↗ 버튼, 공지 상세의 ↗ 버튼 | 웹 공지 페이지를 연다. 목록 버튼은 전체, 상세 버튼은 그 공지(`#id`)로 간다. |

두 웹 페이지 모두 `?demo=1`을 붙이면 예시 데이터로 동작한다. 네트워크도 로그인도 쓰지 않고, 아무것도 저장하지 않는다.

## 파일

- `backend/migrations/006_announcements_admin.sql`: 관리자 목록 표, `is_app_admin()`, 관리자 전용 쓰기 정책. **11/02 운영에005와 함께 적용 완료.** 클라우드 수명주기의006과 구분한다.
- `landing/notices/index.html`: 공개 페이지.
- `landing/admin/notices/index.html`: 관리자 페이지. 검색에서 빠지도록 `noindex`를 넣었다.
- `landing/assets/notices-common.js`: 두 페이지가 같이 쓰는 코드와 데모 데이터.
- `landing/assets/notices-config.js`: 공개 Supabase URL과 anon 키. 앱에 들어 있는 것과 같은 공개값이다.
- `landing/vercel.json`: `/admin/*`에 `X-Robots-Tag: noindex`와 `no-store`를 붙였다.
- `landing/robots.txt`: `/admin/`을 막았다.
- `landing/sitemap.xml`: `/notices`를 추가했다.

## 운영에 올리는 순서 (승인 후)

1. Supabase SQL 편집기에서 `005_app_announcements.sql`, 그다음 `006_announcements_admin.sql`을 실행한다.
2. Supabase → Authentication → URL Configuration → Redirect URLs에 `https://hum-track.com/admin/notices`를 추가한다.
3. 랜딩 사이트를 배포한다 (Vercel).
4. 확인:
   - `humtrack@gmail.com`으로 관리자 페이지에 로그인한다.
   - 초안을 저장한 뒤 공개 페이지에 안 보이는지 확인한다.
   - 게시를 켠 뒤 공개 페이지와 앱에 보이는지 확인한다. 앱은 다시 열면 바로, 아니면 최대 15분 뒤에 보인다.
   - 다른 Google 계정으로 로그인하면 "권한이 없어요"가 나와야 한다.

## 동작

- **종류**:
  - 소식: 목록에만 보인다.
  - 중요: 앱 홈 배너에 보인다.
  - 긴급: 앱을 열면 팝업으로 한 번 뜨고, 확인하기 전까지는 앱을 새로 열 때마다 다시 뜬다.
- **초안 / 게시**: `published`를 끄면 앱과 웹 어디에도 보이지 않는다. 잠시 내릴 때는 삭제하지 말고 게시를 끈다.
- **revision**: 제목, 본문, 종류, 버튼을 바꾸면 DB 트리거가 revision을 올린다. 앱은 이것을 새 공지로 보고 다시 "안 읽음"으로 표시한다.
- **입력 검사**: 관리자 페이지가 표의 규칙(ID 형식, 길이, 기간, 버튼 링크 허용 목록)을 저장 전에 같은 내용으로 미리 검사한다. 서버도 같은 규칙으로 다시 막는다.

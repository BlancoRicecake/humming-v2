- **ID:** ui-001
- **Status:** draft (설계 확정, 구현 전)

- **기준 코드:** `develop` 88d51a6 (v1.0.13+43)
- **디자인 원본:** Claude Design 캔버스 "HumTrack UI/UX 작업실" › 3. 프로그램 (Windows) › 후보 B2 (https://claude.ai/artifact/124szsrF9A6xfYBgGqC9dL, 비공개). 이 문서만으로 구현할 수 있게 화면을 글로 옮겼다. 캔버스와 이 문서가 다르면 이 문서를 따른다.

## 왜 하는가

1280×720 창에서 지금 편집기는 가로줄 15개(상단 바, 섹션, 타임라인 머리글, 트랙 머리글, 트랙, 스크롤바, 분할 핸들, 구간 반복 바, Solo 안내, 표면 머리글, 키 안내, 도구 줄, 눈금, 노트, 강약 막대, 재생 바)가 위아래로 쌓여, 노트를 고치는 피아노롤이 약 138px(24px 음 줄 5개)밖에 안 된다. 폰 화면을 세로로 늘린 구조라 데스크톱의 가로 폭을 쓰지 못한다. 도구 40여 개가 한 줄 가로 스크롤에 몰려 있고, 그루브·펼치기·코드 종류는 아래에서 올라오는 시트로만 바꿀 수 있다.

목표는 우선 사용자(취미 초보자)가 데스크톱에서 "곡 전체를 보는 일"과 "한 트랙을 고치는 일"을 각각 넓은 화면에서 하게 하는 것이다.

| 1280×720 기준 (계산치) | 피아노롤 높이 | 보이는 음 줄 |
|---|---|---|
| 지금 (develop) | 약 138px | 약 5줄 |
| B2 편집 보기 | 약 500px | 약 20줄 |

## 범위와 원칙

- **데스크톱에서만 바뀐다.** 모든 레이아웃 변경은 `_EditScreenState._desktop`(Windows·macOS·Linux, 테스트는 `EditScreen.debugDesktopOverride`)이 참일 때만 적용한다. 폰·패드 화면과 동작은 그대로다. 예외는 0단계(앱 테마)뿐이며, 이것은 모든 기기에 적용되는 것이 의도다.
- **곡 데이터 형식은 바꾸지 않는다.** 새로 저장하는 값은 `LoopPrefs`의 UI 설정뿐이다.
- **기존 기능은 하나도 없애지 않는다.** 자리만 옮긴다. 옮긴 기능은 아래 "기능 이동표"에 모두 적는다.
- **기존 `ValueKey`는 유지한다.** 위젯을 옮겨도 같은 키를 붙인다. 테스트는 위치가 아니라 키로 찾으므로, 데스크톱 경로에서 위치에 의존하던 테스트만 고친다.
- **색·반경·글꼴은 `LT`, `LTRadius`, `LTType` 토큰만 쓴다.** `Colors.*` 직접 사용, 새 하드코딩 색 금지.
- **새 문구는 ARB(`app_ko.arb`, `app_en.arb`)에 넣는다.** 코드 안 `ko ? … : …` 분기를 새로 만들지 않는다. 옮기는 위젯의 기존 인라인 문구는 그 단계에서 ARB로 옮긴다.
- **버튼 크기:** 데스크톱 아이콘 버튼은 36px 이상, 텍스트 버튼은 높이 30px 이상. 모든 아이콘 버튼에 툴팁을 달고, 단축키가 있으면 툴팁에 함께 적는다.
- **기준 화면:** 1280×720에서 설계하고, 960×600(앱 최소 창)에서 깨지지 않는지, 1920×1080에서 남는 공간이 피아노롤·트랙으로 가는지 확인한다. (기준 크기는 추천안이며 Heo 확정 전이다. 바뀌면 이 줄과 수용 기준의 숫자만 고친다.)

### 오른쪽 인스펙터 (280, 4단계)

- 바탕 `LT.surface`, 왼쪽 1px `border`. 맨 위 44: 탭 "트랙" | "노트 N"(선택 노트 수) + 접기 버튼(`right_panel_close`). 접으면 40px 세로 막대(탭 아이콘 2개)만 남는다.
- **노트를 고르면 노트 탭으로, 선택이 없어지면 트랙 탭으로 자동 전환한다.** 사용자가 직접 탭을 누르면 그 선택을 다음 자동 전환까지 유지한다.
- **트랙 탭:** 트랙 아이콘 타일(40, 트랙색 12%) + 역할 이름(14/w800, 예: Melody) + "노트 N개 · M마디" · 악기(누르면 기존 악기 시트) · 볼륨 슬라이더 · Pan 슬라이더(더블클릭·Alt+클릭 초기화, 믹서와 같은 핸들러) · Solo / 음소거 버튼 · 그루브(기존 그루브 시트) · 허밍으로 노트 넣기 · MIDI 구간 가져오기(기존 섹션 가져오기 흐름) · 트랙 비우기.
- **노트 탭:** 제목 "선택한 노트 N개" + 음 이름 목록(Mono 11) · 위치 ← → ♭ ♯ · 옥타브 −1/+1 · 길이 −/값/+ · 강약 슬라이더 · 확률 · 세기 변화 · 격자 맞춤/자유 이동 · 줄 단위 메뉴(높이 34, 오른쪽 `chevron_right`, 누르면 기존 설정 시트): 퀀타이즈 · 코드 깔기 · 펼치기 · 더 보기(자르기·붙이기·이어 붙이기·휴머나이즈·스케일에 맞추기) · (기타 트랙만) 기타 스트로크·줄 · 아래 고정 4칸(높이 48): 복제 · 소리 끄기 · 잠금 · 삭제(글자 `#FCA5A5` 대신 `LT.danger`).
- 드럼 그리드 "선택" 모드의 인스펙터 항목(←, →, 세기, 퀀타이즈, 휴머나이즈, 확률, 세기 변화, 삭제, 소리 끄기)도 같은 노트 탭에 들어간다.

### 단축키

기존 단축키는 모두 유지한다. 새 단축키는 패드 모드의 연주 키(A S D F G H J K L ; ' \)와 피아노롤 단축키(M, C, G, I 등)와 겹치지 않게 정한다. 캔버스 목업의 툴팁에 적힌 한 글자 단축키(L, H, I, F)는 충돌하므로 아래로 바꾼다.

| 동작 | 단축키 |
|---|---|
| 편곡 ↔ 편집 보기 | Tab (글자 입력 중이 아닐 때. Flutter 포커스 이동보다 먼저 처리) |
| 선택한 트랙을 편집 보기로 | Enter (편곡 보기에서) |
| 구간 반복 켜기/끄기 | Ctrl/Cmd+L |
| 허밍으로 넣기 | Ctrl/Cmd+Shift+H |
| 인스펙터 접기/펼치기 | Ctrl/Cmd+I |
| 믹서 | Ctrl/Cmd+M |
| 단축키 보기 | F1, Ctrl/Cmd+/ |

단축키 보기 창은 `DesktopCommands`와 피아노롤 단축키를 하나의 목록 데이터에서 만들어, 툴팁과 같은 출처를 쓴다.

## 단계

단계마다 `develop`에서 브랜치 하나 → 구현 → `flutter analyze`·전체 테스트 → Windows 빌드로 직접 확인 → PR. 앞 단계가 머지된 뒤 다음 단계를 시작한다.

### 0단계 — 앱 테마로 시트·창 모양 통일 (모든 기기)

**문제.** `loopTapTheme()`(`theme/tokens.dart`)는 `ThemeData.dark(useMaterial3: true)`에 primary·surface만 바꿔서, 테마 기본값을 쓰는 시트와 창(펼치기, 코드 종류, 퀀타이즈·휴머나이즈, 그루브, 기타 스트로크, 자르기, MIDI 가져오기, 그루브 이름 바꾸기, 곡 이름·삭제, 설정·계정의 확인 창 등)이 M3 기본 보라빛 바탕·칩·슬라이더로 뜬다.

**변경.** `loopTapTheme()` 한 곳에 아래 기본값을 넣는다. 시트 파일의 레이아웃은 바꾸지 않는다.

## 열린 질문

- 기준 화면 크기 확정 (추천: 1280×720 기준, 960×600 확인).
- 편곡 보기 트랙 줄 높이 64가 트랙이 많을 때도 괜찮은지 (8개 이상이면 44로 줄이는 안).
- 믹서 시트를 더 보기 메뉴에 둘지, 상단 바 아이콘으로 남길지 (지금 설계: 더 보기 메뉴 + Ctrl+M).

- **변경:** 변환 콜백이 성공/실패/취소를 구분해 반환한다. 실패하면 녹음창이 유지되고 오류 설명·녹음 보관 안내·‘같은 녹음으로 다시 시도’가 표시된다. 6초 알림에만 있던 재시도와 실패 후 성공 표시는 제거했다.
- **보관:** 모달이 변환용 임시 파일을 소유하며 재시도마다 같은 경로와 내용을 사용한다. 성공 또는 확인한 폐기 시 정리한다. 폐기 전 확인창을 제공하고, 사용 중인 파일은 콜백 종료 후 지운다. 기존 가이드의 원본 비교용 복사본 수명은 유지한다. 앱 강제 종료·재시작 후 복구는 이번 구현에 포함하지 않는다.
- **취소/접근성:** 연속 클릭은 하나의 변환만 실행한다. 폐기를 선택하면 요청을 취소하고 늦게 도착한 응답이 음표를 추가하지 못하게 한다. 폐기 확인 중 성공하면 확인창도 닫는다. 새 행동은 Flutter 표준 버튼(최소 높이 48)이며 실패 안내에 live region을 제공한다. 영어 보관 행동은 `Keep this recording`으로 구분했다.
- **검증:** 관련 8개 파일의 위젯 테스트 **70개 통과**, 기존 테마 테스트 **3개 건너뜀**. 새 허밍 회귀 테스트 9개는 30초 후 파일 유지, 동일 파일 재시도, 반복 실패, 폐기 확인, 중복 요청 방지, 취소·외부 dispose와 지연 정리, 키보드 Enter 취소, 확인창 도중 성공, 한국어/영어 640×320 스크롤 접근, 실제 편집기 오류 전달을 포함한다. `flutter analyze --no-pub`는 오류·경고 없음. 로그는 `artifacts/hum-retry-20261104/regression-tests.log`, `analyze.log`다.
- **독립 검토:** UI Craft의 읽기 전용 디자인/접근성 검토를 수행했다. 취소 버튼의 키보드 접근과 영어 문구 지적을 반영했다. 실제 마이크·실서버 변환·OS 화면낭독기 동작은 검증하지 않았다. 편집기 오류 테스트는 Flutter 테스트용 HTTP 400 응답을 쓰므로 실서버 요청이 아니다.

기존 미커밋 작업을 보존했고 UX-02~05는 이 변경에서 수정하지 않았다. 다음 권장 작업은 첫 곡 비교 화면의 재녹음(UX-02)이다.

**코드로 확인:** [호스트의 변환 실패 처리](../../../mobile/lib/looptap/screens/edit_screen.dart:4913)는 오류를 잡고 정상 반환한다. [녹음창](../../../mobile/lib/looptap/widgets/sheets/hum_modal.dart:438)은 콜백 반환 후 성공 여부와 무관하게 `done`으로 바꾸고 650ms 뒤 닫는다. [완료 문구](../../../mobile/lib/l10n/app_ko.arb:860)는 ‘완료! 노트를 넣었어요.’다. 호스트의 [6초 재시도 알림](../../../mobile/lib/looptap/screens/edit_screen.dart:4926)이 행동 없이 닫히면 해당 변환용 임시 파일을 지운다.

**구분:** 기존 곡 전체나 영구 보컬 파일이 삭제된다는 뜻이 아니다. 가이드에는 세션 중 비교용 복사본도 있지만, 이 복사본으로 재시도하는 사용자 경로는 연결돼 있지 않다. 문제는 **실패에 대한 성공 표시와 일시 알림에만 의존하는 재시도**다.

**적용 원칙:** UI Craft 상태 가시성·오류 복구, HumTrack brief의 ‘내가 부른 멜로디를 지킨다’와 ‘다음 행동이 보인다’.

**완료 기준:** 성공일 때만 성공 표시한다. 오프라인·서버 오류·음표 없음·대상 변경은 실패 상태로 남으며, 30초 후에도 같은 녹음을 다시 분석할 수 있다. 사용자가 취소/폐기를 선택하거나 성공하기 전까지 필요한 녹음을 보존한다. 기존 곡의 음표는 실패 시 바뀌지 않는다.

### UX-02 — 비교한 자리에서 다시 부르기

**코드로 확인:** [재녹음 버튼](../../../mobile/lib/looptap/widgets/guided_hum_panel.dart:239)은 `addTrack`일 때만 나온다. [첫 곡의 호출부](../../../mobile/lib/looptap/screens/edit_screen.dart:5361)는 이 플래그를 주지 않는다. [뒤로가기](../../../mobile/lib/looptap/screens/edit_screen.dart:5183)는 첫 곡 경로에서 이전 녹음 단계로 돌아가는 대신 저장 후 편집기를 나간다.

**개선의 주의점:** `_humConvert`의 현재 적용 방식은 음표 추가(`addAll`)다. 기존 콜백만 ‘다시 녹음’에 연결하면 두 녹음의 음표가 겹칠 수 있다. 첫 곡 재녹음은 ‘추가 녹음’과 구분해 교체 의미를 갖게 한다.

**완료 기준:** 원본/악기 듣기 → 다시 녹음 → 비교가 한 화면 흐름으로 이어진다. 새 변환 성공 전에는 이전 결과를 유지하며, 실패·취소 시 복구되고 성공 시 한 번의 실행 취소로 이전 멜로디로 돌아갈 수 있다.

### UX-03 — 데스크톱 기본 포커스 탐색 복구

**코드로 확인:** [단축키 목록](../../../mobile/lib/looptap/widgets/shortcut_help.dart:78)이 수정키 없는 Tab을 `viewToggle`로 등록한다. [이벤트 처리](../../../mobile/lib/looptap/widgets/desktop_workspace.dart:118)는 이 이벤트를 처리 완료로 소비한다. 텍스트 입력과 모달에는 예외가 있지만 일반 편집기에는 적용되며, [보기 전환](../../../mobile/lib/looptap/screens/edit_screen.dart:2506)은 명령 영역으로 포커스를 돌린다.

**완료 기준:** 일반 Tab/Shift+Tab이 지원되는 컨트롤의 전후 탐색을 수행하고 화면 보기를 바꾸지 않는다. 보기 전환은 기존 ‘편곡/편집’ 컨트롤에서 계속 가능하다. 그리드·제목 입력·모달의 기존 키 동작을 함께 확인한다.

### UX-04 — 사용자가 요청한 큰 글자 존중

**코드로 확인:** [앱 루트](../../../mobile/lib/looptap/app.dart:45)의 `MediaQuery.withClampedTextScaling`이 모든 하위 화면에 최대 1.15배를 적용한다.

**완료 기준:** 1.0/1.5/2.0 배율에서 녹음 안내·오류·재시도·악기 선택·저장·설정 등의 핵심 문구와 행동에 접근할 수 있다. 정해진 높이의 편집 셀·계기 숫자가 예외라면 해당 영역만 따로 설계하고 앱 전체를 축소하지 않는다.

Flutter도 OS의 글자 설정을 존중하고 큰 글자에서 레이아웃을 확인하도록 안내한다. [공식 기준](https://docs.flutter.dev/ui/accessibility/ui-design-and-styling)

### UX-05 — 재생과 녹음 버튼을 읽고 조작할 수 있게

**코드로 확인:** [휴대폰 하단 재생](../../../mobile/lib/looptap/widgets/transport_bar.dart:120)과 [녹음](../../../mobile/lib/looptap/widgets/transport_bar.dart:148)은 아이콘/도형 중심이며 상태를 알리는 Tooltip/Semantics 이름이 없다. 실제 일반 편집기의 [연결 경로](../../../mobile/lib/looptap/screens/edit_screen.dart:5521)도 확인했다. 낭독기의 실제 음성 출력은 이번에 실행하지 않았으므로 플랫폼별 최종 증상은 확인이 남는다.

**완료 기준:** 화면낭독기가 ‘재생/일시정지’, ‘녹음 시작/녹음 종료’, 사용할 수 없는 상태를 구분해 전달한다. 키보드로 포커스 가능한 버튼은 Enter/Space로 동작하며, 아이콘 외형을 유지하더라도 휴대폰 실제 터치 영역은 Android 48 / iOS 44 logical 기준을 충족하도록 레이아웃을 확인한다. [Flutter 터치·이름 검사 기준](https://docs.flutter.dev/ui/accessibility/accessibility-testing)

## 같은 공통 컨트롤 정비에서 함께 다룰 항목

상위 5개 외에도 작은 조작 영역이 확인됐다. 폰 [상단 버튼 크기 30](../../../mobile/lib/looptap/screens/edit_screen.dart:5639)을 공용 [IconBtn](../../../mobile/lib/looptap/theme/atoms.dart:59)이 그대로 실제 영역으로 사용한다. 데스크톱 [구간 구성 띠의 높이는 16](../../../mobile/lib/looptap/widgets/desktop_section_band.dart:48)이며 추가·전체 곡 듣기 행동도 그 안에 있다. 폰은 외형과 터치 영역을 분리하고, 데스크톱 구성 띠는 28px 정도의 실제 상호작용 높이를 확보하는 작은 변경을 권한다. 이는 이번에 측정한 오입력률이 아니라 코드 크기에 근거한 사용성 위험이다.

첫 곡 상단의 ‘1 녹음 → 2 저장’과 실제 편집기 인계의 관계도 문구 정비 후보로 기록한다. 자동 저장은 구현돼 있으므로 ‘저장 기능이 없다’고 판단하지 않는다. 초보자에게 저장 완료와 다음 행동이 어떻게 이해되는지 관찰한 뒤 문구를 맞춘다.

## 권장 진행 순서

1. **첫 작업 — UX-01.** 허밍의 성공/실패 결과와 파일 보존·재시도 흐름만 수정한다. 성공·실패·취소에 같은 녹음/기존 곡이 어떻게 남는지 확인한다.
2. **두 번째 — UX-02.** 첫 곡 비교 화면의 재녹음을 추가한다. 결과 교체·원본 비교·취소·Undo까지 한 흐름으로 검증한다.
3. **접근성 정비 — UX-03~05.** Tab 선점 제거, 전역 글자배율 개선, 공통 버튼의 이름·상태·키보드·터치 범위를 작은 변경으로 나눈다. 녹음/재생 고빈도 입력의 지연이 늘지 않아야 한다.
4. **그다음 — 설명 없이 첫 곡 관찰.** 초보자 5명이 녹음 → 비교 → 편집 → 저장까지 진행하는 모습을 확인한다. 편집기 인계 뒤 반주·구성·저장의 실제 막힘을 찾고 다음 화면 설계를 결정한다. 기존 ‘5명 중 4명, 3분 안에 저장’은 목표이지 이번 검토의 달성 결과가 아니다.

## Passed / Left alone

- 첫 곡은 로그인 선행 없이 가이드에 진입하는 코드 경로가 있다. 처음에 허밍 변환과 목소리 녹음을 문장으로 구분하고 인터넷 필요를 알린다.
- 성공 결과를 원본 허밍과 악기 멜로디로 비교하는 경로와 악기·키 선택이 있다. 자동 저장·뒤로 나가기 저장·저장 실패 시 편집 유지도 구현돼 있다. 실기기 저장 신뢰성을 통과 처리한 것은 아니다.
- 데스크톱의 키 안 음 필터, 주요 허밍 버튼, 강약 막대 기본 접힘, 인스펙터는 최근 개선 사항이므로 ‘없다’고 재지적하지 않았다.
- 기존 어두운 배경·라임색·트랙별 색상은 유지 대상이다. UI Craft의 일반 웹 스타일을 이유로 새 팔레트·프레임워크·전면 재설계를 제안하지 않았다.
- 가격/무료 공유/클라우드/AI 편곡·엔진 교체·출시 상태는 이번 판정 대상이 아니다. 실제 녹음·오디오 지연·청취와 스토어 상태도 확인하지 않았다.

## 검증의 범위와 한계

- 이번 확정 문제는 현재 소스의 실제 import·분기·콜백 연결을 추적한 결과다. 정적 코드의 사실과 사용자에게 미칠 영향의 추론을 구분했다.
- 설치된 Windows 바이너리/과거 `artifacts/ui-005-beginner-polish/` 화면은 현재 소스보다 이전 상태이므로 현행 실행 검증으로 취급하지 않았다. 사용자 환경의 앱을 실행하거나 기존 곡을 조작하지 않았다.
- 현재 `GuidedHumPanel`을 직접 렌더한 별도 검토용 harness는 1개 테스트에서 한국어/영어, 844×390/1280×720 조건을 실행해 예외 없이 통과했다. 하지만 테스트용 폰트 대체와 일부 캡처의 불완전한 글리프/페인트가 확인돼 **캡처는 현재 제품의 픽셀·글꼴 품질 증거로 채택하지 않았다.** 캡처 이상을 제품 버그로도 기록하지 않았다. 자료와 로그는 `artifacts/uiux-review-20261104/`에 있다.
- VoiceOver/TalkBack/Narrator, 실제 마이크, OS 포커스 이동, 실기기 글자 확대·탭 정확도, 변환 성공률, 첫 곡 완성 시간은 추가 검증이 필요하다. 점수나 사용자 실패율을 추정해 적지 않았다.

## Verdict

첫 개선은 **허밍 변환 실패를 성공으로 표시하지 않고, 같은 녹음으로 다시 시도할 수 있게 하는 것**이다. 이어 비교 화면의 재녹음과 기본 접근성을 다듬은 뒤 실제 초보자 관찰로 편집기 인계의 다음 우선순위를 정한다. 이번에는 제품 소스를 변경하지 않았다.

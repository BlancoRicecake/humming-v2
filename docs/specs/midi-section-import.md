# MIDI 구간을 기존 곡의 새 섹션으로 추가 (설계 초안)

- **상태:** implemented (2026-10-23, 커밋 전). Codex 검토 조건 1–8을 반영했다. 구현 메모는 맨 아래 "구현 메모"에 있다.
- **근거:** 곡 완성 실증(`artifacts/song-e2e-20261023/plan.md`)에서 처음 만난 큰 장애다.
  - 지금 MIDI 가져오기는 1–8마디 구간으로 **새 곡만** 만든다(`songs_screen.dart:42-51`, `midi_import_sheet.dart:68-90` `MidiReference.passage` → `Song`).
  - 그래서 Verse를 가져온 뒤 Intro·Chorus·Break·Outro의 수백 노트를 그리드에 다시 입력해야 한다.
  - 가져오기마다 무료 곡 한도도 하나씩 쓴다.

## 사용자 동작
1. **진입:** 편집 화면 섹션 메뉴(섹션 길게 누르기 / 우클릭)의 **[MIDI 구간을 새 섹션으로]**. 데스크톱은 섹션 바 `+` 옆 메뉴로도 들어간다. 곡 목록의 `MIDI +`(새 곡 만들기)는 그대로 둔다.
2. **구간 선택:** 파일을 고르면 기존과 같은 구간 선택 창이 열린다(시작 마디, 길이 1/2/4/8, 파트 선택). 길이 8은 기존 가져오기와 같이 섹션 모델이 허용한다.
3. **파트 → 트랙 대응표:** MIDI의 각 파트를 다음 중 하나에 연결한다.
   - 이 곡의 같은 종류 트랙 (멜로디류 → 멜로디/멜로디2/베이스, 드럼 → 드럼/비트필)
   - 새 추가 트랙 (빈 채널이 있을 때만)
   - 건너뛰기

   기본값은 GM 프로그램과 채널로 추정한다(드럼 채널 → 드럼, 베이스 프로그램 32–39 → 베이스, 나머지는 순서대로). 한 트랙에 두 파트를 연결할 수는 없다.
4. **충돌 안내 (자동 변환 없음):**
   - **BPM:** 파일 템포와 곡 템포가 다르면 "곡 템포(N)를 유지합니다. 마디 단위 위치는 같고 빠르기만 곡을 따릅니다"라고 안내한다. 곡 BPM은 바꾸지 않는다.
   - **조성:** 곡 키·스케일 밖 음이 몇 개인지 표시한다. 조옮김·스케일 맞추기는 하지 않고, 기존 [스케일 맞추기] 도구를 안내한다.
   - **악기:** 기존 트랙의 악기는 바꾸지 않는다. 파일의 GM 프로그램은 정보로만 보여 준다. 새로 추가하는 트랙에만 파일 프로그램을 기본값으로 쓴다(선택 가능).
   - **거절 조건:** 4/4가 아니거나 템포가 변하면 기존 가져오기와 같은 기준으로 거절하거나 참고용으로만 표시한다.
5. **결과:** 현재 섹션 **바로 뒤에 새 섹션 하나**를 만든다.
   - 이름은 파일 이름과 구간(예: `verse.mid [1–4]`), 반복 ×1, 연결 없음.
   - 대응한 트랙에만 노트를 넣고, 나머지 트랙은 빈 상태로 둔다.
   - **실행 취소 한 번**으로 섹션 추가 전체를 되돌린다. 새 트랙을 만들었다면 그것도 함께 되돌린다.
   - 곡 한도를 쓰지 않는다(새 곡이 아니므로).
6. **결과 안내:** "섹션 'X' 추가 · 노트 N개 · 건너뛴 파트 M · 스케일 밖 K"

## 보호·불변 조건
- 기존 섹션·트랙·노트·클립·믹스 값은 바뀌지 않는다(의미 단위 JSON 비교, 날짜·메타 제외). 섹션 목록에 새 섹션 하나가 삽입될 뿐이다.
- 곡 BPM·키·스윙·악기는 바뀌지 않는다. 새 추가 트랙의 악기는 예외다.
- 노트 변환은 기존 `MidiReference.passage`의 계산(16분 스텝, 미세 오프셋, 세기 보존)을 **그대로 재사용**한다. 결과 섹션의 노트는 같은 구간을 새 곡으로 가져왔을 때의 첫 섹션 노트와 같다.
- 결제·한도 정책은 바꾸지 않는다.

## 구현 범위 (작게)
- `MidiReference.passage(...)`를 그대로 호출해 임시 `Song`을 만든다. 그 첫 섹션의 트랙들을 대응표대로 새 `Section`에 옮기는 순수 함수 `sectionFromPassage(song, tmpSong, mapping) → (Section, newTrackRefs, report)`를 추가한다.
- UI: 기존 `_MidiPassageDialog`를 재사용하고, 대응표와 안내를 추가하는 작은 확장 + 섹션 메뉴 항목. 편집 화면에서는 `_pushUndo` 한 번 후 삽입한다.
- 모델·스키마 변경은 없다.

## 구현 메모 (2026-10-23, 커밋 전)
- **코드:** `mobile/lib/looptap/music/midi_section_import.dart`(순수 함수), `mobile/lib/looptap/widgets/sheets/midi_import_sheet.dart`(`pickMidiSection`, `showMidiSectionDialog`, 대응표·안내가 붙은 `_MidiPassageDialog` 섹션 모드, 주입 가능한 `MidiFilePicker`), `mobile/lib/looptap/screens/edit_screen.dart`(섹션 메뉴 항목 `section-midi-import`, `_importMidiSection`, 테스트용 `EditScreen.midiFilePicker`).
- **노트:** 대응한 파트마다 `MidiReference.passage(selectedLanes: {그 파트})`를 따로 불러 노트를 그대로 옮긴다. 임시 곡의 트랙 id가 아니라 파트 id로 대응하므로, 새 곡 가져오기(파일 순서대로 melody/melodyDec/bass)와 섹션 기본 대응(GM 휴리스틱)이 달라도 노트 값(pitch·freq·velocity·step·dur·offsetSteps·durationSteps)은 같다. 기존 새 곡 가져오기 코드는 바꾸지 않았다.
- **기본 대응:** 드럼 채널 → drums, beatDec, 추가 드럼 트랙. GM 32–39인 첫 파트 → bass. 나머지는 순서대로 melody, melodyDec, 그다음 비어 있는 멜로디류 대상. 남는 파트는 건너뛴다(새 트랙은 기본값으로 고르지 않는다). 다른 파트가 이미 고른 트랙은 목록에서 비활성이다.
- **새 트랙:** 채널은 기존 규칙(`sectionTrackMetas`, 섹션별 추가 트랙 순서)으로 정해진다. 모든 섹션에서 같은 채널이고, 어떤 섹션의 트랙도, `ArticulationPlan`의 주법 채널도 쓰지 않을 때만 고를 수 있다. 아니면 이유(채널 한도 / 기타 주법 채널 / 섹션별 트랙 구성 불일치)와 함께 비활성이다. 악기는 "새 트랙에 파일 악기 사용"(기본 켬)일 때 파일의 GM 프로그램, 끄면 트랙 종류 기본값이다. 새 트랙 종류는 기존 가져오기와 같이 `melody`(멜로디류) / `drums`이다.
- **스펙과 다른 점:** 트랙 구성은 곡 전체가 같아야 채널이 어긋나지 않는다(`_addTrack`, `addVocalMidiTrack`과 같은 규칙). 그래서 새 트랙을 고르면 기존 섹션에도 그 트랙의 **빈 레인**이 추가된다. 기존 트랙·노트·링크·이름·반복은 그대로이며, 테스트는 새 트랙 id를 뺀 의미 단위 JSON이 같은지 확인한다. 새 트랙을 고르지 않으면 기존 섹션 JSON은 그대로 같다. 또한 삽입 후 자동 이름(A, B…)을 다시 매기지 않는다(기존 섹션 이름 보존).
- **진입:** 섹션 칩 길게 누르기 / 우클릭 메뉴만. 데스크톱 `+` 옆 별도 메뉴는 만들지 않았다(같은 우클릭 메뉴로 들어간다).
- **테스트:** `mobile/test/looptap/midi_section_import_test.dart` (11개).

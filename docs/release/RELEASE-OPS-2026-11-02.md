# 출시 운영 준비 후속 결과

후속 보안 점검: [SECURITY-REVIEW-2026-11-02.md](SECURITY-REVIEW-2026-11-02.md).
아래 후보는 보안 수정 전 이력이다. 새 `backend-candidate-20261102-security`의
335개 회귀·17개 격리 검사와 별도로 네이티브 파서 경고가 남아 있어 출시 보류다.

2026-11-02 KST. `C:/src/humming-v2`, 현재 수정본 기준.
**공개 출시 보류.** 앱/기기 테스트는 사용자가 진행한다. 이번 작업에서는 앱 소스,
Android 내부 테스트44, Windows44 설치본을 변경하지 않았다. Git push·PR·원격 CI 실행,
서버 배포·운영 DB 변경·클라우드 공개·고객 공지·메일도 하지 않았다.

## 이번에 완료한 일

1. **작업자 생존·실패·적체 점검 구현.** migration008과 `app.cloud_monitor`를 추가했다.
   API lifespan이 같은 공용60초 루프를 사용하며 수동 정리와 예약 실행을 구분한다.
   큐가 비어 있어도 예약 작업자가 없거나 마지막 성공이 오래됐으면 정상으로 판정하지 않는다.
2. **스테이징008 적용·실제 주기 실행.** 기존에 승인된 스테이징 관리자 키→기존 Fly
   humming-api 머신의 일회성 메모리 검증을 이어갔다. 현재5개 모듈만 별도 프로세스에
   로드하고 포트·설정·Fly 시크릿을 바꾸지 않았다. DSP/main 전체를 운영 머신에 중복
   로드하지 않았다. 로컬 API lifespan 연결은 전체 회귀에서 별도로 확인했다.
3. **기존 QA 잔여 정리 완료.** 앞선 시험 계정2개만 있고 Auth 사용자/프로젝트0개,
   삭제 요청일·URL 유예 경과·QA lease 형식이 맞는지 확인한 뒤 실제 정리 루프를 실행했다.
   첫 pass는2개 계정,60초 뒤 두 번째 pass는0개 계정을 처리했고 둘 다 정상 heartbeat를 남겼다.
   임의로 시각을 당기지 않았다. R2 두 경로가 비었고 primary purge2개가 확인됐다.
4. **관리 점검 접근 차단.** 익명/일반 사용자에게 private 표·점검/기록 RPC 접근을
   허용하지 않았다. 실제 공개 키 REST11항목과 카탈로그/ACL24개가 모두 통과했다.
5. **새 로컬 서버 후보 검증·보존.** 현재 backend로 이미지 빌드,1CPU/1GB·네트워크 차단
   컨테이너의 health·음원11개·부분 다운로드/해시·WAV/Opus 분석·MIDI12항목 통과.
   QA 컨테이너는 정리하고, 검증 이미지와 오프라인 TAR은 보존했다.
6. **비활성 원격 감시 준비.** read-only SSH 점검 전달기와15분 주기 워크플로를 준비했다.
   저장소 변수로 명시적으로 켜기 전에는 실행되지 않는다. 원본 SSH 출력 대신 알려진
   상태 코드만 로그에 남긴다. 저장소의 `FLY_API_TOKEN` 이름이 없음을 확인했으며
   토큰 생성·등록·변수 변경·워크플로 실행·알림 발송은 하지 않았다.

## 점검 설계와 경계

- heartbeat 표는 무작위 **작업자 프로세스 UUID**, 시작/종료/마지막 성공 시각, 상태,
  허용된 숫자 카운터만 저장한다. 고객 UUID/키/곡명/예외 원문은 저장하지 않는다.
- 작업자 기록은7일 뒤 정리한다. 고객 탈퇴 tombstone의 최종 보관 정책과는 별개다.
- 미실행, 마지막 성공5분 초과, 실행 중2분 초과, 실패 pass, 삭제 작업1시간 초과,
  계정 스캔10분 지연, Auth 삭제/유예 후 primary purge15분 초과를 감지한다.
  이 수치는 운영 알림 기준이며 고객 삭제 완료 시한을 약속한 것이 아니다.
- 실패한 pass는 고정된 오류 문구를 남겨 기존 Sentry 로깅 연동에서 구분할 수 있다.
  실제 Sentry 알림 규칙·담당자 수신은 아직 연결/검증되지 않았다.
- 운영 CLI `python -m app.cloud_monitor`는 읽기만 한다. 정리 CLI `cloud_cleanup --apply`와
  다르다. 수동 pass가 성공해도 예약 작업자 생존 증거로 쓰지 않는다.
- 새 소스를 운영에 올리기 **전에008까지 적용**해야 한다. 이전 스키마로 새 작업자를
  켜면 heartbeat/RPC 누락으로 실패한다. public 유지보수·삭제 endpoint는 만들지 않았다.

전체 백엔드 테스트의11skip은 옛 live 테스트다. 실제 구독 구매/만료, 두 네이티브 기기 왕복,
R2 부분 삭제 장애·API 응답 유실의 실서비스 재현, 지속 운영·관측은 아직 별도 검증이다.

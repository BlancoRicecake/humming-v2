# 앱 업데이트 전 수정 — 2026-09-11

## 수정

- 저장 실패를 호출자에게 전달한다. 곡 목록은 디스크 저장 성공 후에만
  갱신하며, 실패한 삭제 작업은 보컬 정리를 실행하지 않는다. 자동 저장,
  수동 저장, 이름 변경, 삭제는 순서대로 처리하고 실패 뒤 재시도할 수 있다.
- 편집 화면의 저장/뒤로가기 실패 시 화면과 수정 내용을 유지하고 안내한다.
  자동 저장 실패도 미저장 상태로 표시한다. 곡 목록의 삭제·복제·이름 변경
  실패 역시 사용자에게 알린다.
- 곡 복제 시 곡 전체 보컬의 경로·파형·녹음 BPM·마디 수를 보존한다.
  원본 삭제 후에도 복제본이 참조하는 보컬을 보존한다.
- 빈 `songs.json`을 손상 파일로 취급해 백업에서 복구한다. 복구할 수 없는
  파일과 손상된 백업은 새 설치로 취급하지 않는다. 손상 파일이 보존된
  동안에는 복구 가능한 보컬을 지우지 않도록 자동 정리를 보류한다.
- iOS/Android 한국어·영어 스토어 설명에서 미제공 클라우드 혜택을 제거하고
  실제 Pro 혜택, 기기 내 저장, Clarity/Sentry 사용을 명시했다.
- 홈에 개정 공지 배너를 추가했다. 요약과 문서 3개를 앱 안에서 확인할 수
  있으며, 확인 기록을 기기에 저장한다. 설정에서 다시 열 수 있다.
- 실제 Android 빌드에서 발견한 Flutter 3.47.1 도구 버전 불일치를 수정했다:
  Gradle 8.14.3 / AGP 8.11.1 / Kotlin 2.2.20. CI에서도 JDK 17로
  Android ARM64 디버그 APK를 컴파일하도록 추가했다.

## 검증

- 모바일 전체 테스트: **143개 통과** (기존 132 + 회귀/공지 검사 11).
- 저장 실패 후 원본 보컬 보존, 실패 이후 재시도, 복제 후 원본 삭제,
  동시 저장 순서, 빈 파일 복구 및 재실행을 임시 파일로 검증했다.
- 한국어·영어 공지: 640×360 가로 화면에서 overflow 없음, 닫기와 확인의
  구분, 확인 상태 파일 저장, 공지 재열기를 widget test로 검증했다.
- Dart 분석: 오류/경고 없음, 기존 info 4개.
- Android ARM64 디버그 APK: **빌드 성공**, JDK 17 + Gradle 8.14.3.
  결과: `mobile/build/app/outputs/apk/debug/app-debug.apk`.
  로그인·결제용 환경 설정을 주입한 배포 빌드가 아닌 컴파일 검증용이다.
  PC 기본 Java 설정은 바꾸지 않고 임시 JDK로 실행했다. Gradle/플러그인의
  향후 버전 관련 deprecation 경고는 남아 있다.

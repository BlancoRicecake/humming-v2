## 코드에서 확인한 점

- 허밍 녹음과 보컬 녹음은 별도 흐름이다. edit_screen.dart의 _humConvert는 EngineApi.analyze로 녹음을 분석해 활성 트랙에 음표를 추가한다. 보컬 편집기의 도구에는 직접 MIDI 변환이 없다.
- 기존 VocalClip은 startStep, trimStart/trimEnd, origPath 및 효과 이력을 갖는다. 새 변환은 클립의 잘라낸 범위와 실제 배치 위치를 존중해야 한다.
- _humConvert는 현재 임시 허밍 녹음을 성공 후, 또는 실패 알림 종료 후 삭제한다. 영구 보컬 경로를 그대로 전달하면 저장된 녹음을 삭제할 위험이 있다. 공통 분석·적용 로직을 분리하고 임시 파일 소유권을 호출 측에서 관리해야 한다.
- 기존 변환은 활성 트랙에 결과를 추가하며 melody 리뷰 UI도 특정 트랙에 결합되어 있다. 새 보컬 변환은 분석 중 트랙을 바꿔도 고정한 대상에만 적용하고, 미리보기 단계까지 프로젝트를 변경하지 않도록 분리한다.
- export_drawer.dart는 파일을 Documents/looptap/exports에 생성하고 공유 화면을 연다. 공유 취소·확인 불가 메시지는 이미 있지만, 파일을 다시 찾고 공유할 지속적인 목록은 별도 개선이 필요하다. “파일 생성”과 외부 앱/폴더에 실제 전달된 결과를 구분한다.
- Windows/Mac 프로젝트 폴더는 존재한다. 이것만으로 녹음·오디오 엔진·로그인·결제·파일 내보내기까지 데스크톱에서 검증되었다고 볼 수 없다.

### 1. 파일 내보내기와 음표 입력 반응성 — 최우선

**내보내기**
- 편집 화면에서 “내보낸 파일” 목록에 접근할 수 있게 한다.
- 생성된 파일의 이름·형식·시각을 표시하고 “다시 공유”, 가능한 플랫폼의 “파일에 저장/저장 위치 선택”을 제공한다.
- 앱 내부 저장 경로만 보여 주고 사용자가 시스템 파일 앱에서 찾을 수 있다고 가정하지 않는다. 실제 지원되는 저장/열기 경로를 플랫폼별로 확인한다.
- 공유 취소·오류에도 생성 파일을 목록에서 다시 찾을 수 있게 하고, 앱 재시작 후에도 유지한다.
- 합격 기준: Android/iPhone 사용자가 내보내기 후 외부 저장 위치를 선택해 파일을 확인하거나, 공유를 취소한 뒤 앱을 다시 열어 같은 파일을 재공유할 수 있다. WAV/MIDI 모두 검사하며 기존 Pro 권한은 유지한다.

**음표 입력 지연**
- 리뷰 기기의 재현 조건을 우선 확인하고 Android/iOS 실제 기기에서 profile/release 모드로 측정한다. 디버그 모드 속도로 판단하지 않는다.
- 입력→음표 표시와 입력→소리 시작 시간을 분리하고, 재생 중/정지 중·짧은 곡/많은 음표 곡을 비교한다.
- 프레임 지연, 전체 화면 재빌드, 파일·음원 로딩, 오디오 호출이 입력 경로를 막는지 측정한 뒤 원인에 맞게 수정한다. 현재 원인을 특정했다고 단정하지 않는다.
- 초기 목표: 기준 기기 60Hz에서 입력→시각 피드백 p95 50ms 이하, 일반 편집 1분 동안 100ms 이상 UI 멈춤 0회, 음표 누락·중복 0회. 오디오 지연은 기기/출력 경로별 기준을 별도로 잡고 Bluetooth는 따로 측정한다.
- 리뷰 작성자와 같은 구버전 문제 재현 여부 및 최신 버전 결과를 구분해서 기록한다.

### 2. 보컬 클립 → MIDI 직접 변환 — 첫 기능 업데이트

사용자 흐름:
보컬 클립 선택 → “악기로 바꾸기 / Convert to MIDI” → 피아노·기타·신스 선택 → 분석 → 원본/악기 미리 듣기 → “악기 트랙 추가”.

- 선택한 한 클립부터 지원한다. 목소리 하나로 부른 멜로디를 초기 지원 범위로 명시하고, 화음·여러 사람·반주가 섞인 녹음이나 말소리가 정확하게 변환된다고 약속하지 않는다.
- 기존 녹음을 다시 녹음하지 않아도 변환한다. 보컬 원본을 남기고 기본적으로 새 악기 트랙에 추가한다.
- 기존 허밍 분석 엔진을 재사용하되 공통 변환 서비스, 임시 오디오 준비, 음표 배치, 미리보기/확정 단계를 분리한다.
- 선택 범위/trim과 startStep, 곡 BPM, 키, 스윙을 일관되게 반영한다. 현재 엔진의 loopBars 범위에서 잘리는 결과가 없도록 제한/분할 정책을 먼저 검증한다.
- 드라이 원본과 효과가 적용된 파일 중 무엇을 분석하는지 명확히 한다. 기본값은 선택 클립의 현재 저장 오디오와 trim 범위이며, 마스터/다른 트랙 반주는 포함하지 않는다.
- 피치 보정 전후 비교와 간단한 옥타브·박자 수정을 제공한다. 첫 화면에는 악기 선택과 미리 듣기를 중심으로 배치한다.
- 분석 요청 시 선택된 오디오 범위가 서버로 전송됨을 기존 정책과 맞게 안내한다. 필요한 범위만 임시 파일로 준비한다.
- 진행·취소·재시도, 무음/음표 없음/긴 파일/서버 혼잡/오프라인을 다룬다. 실패 시 가짜 멜로디를 성공 결과로 보여 주지 않는다.
- 적용 전에는 곡을 변경하지 않는다. 적용은 Undo 한 번으로 되돌리고 저장·재시작 후에도 원본과 결과가 유지되어야 한다.
- 여러 번 누르기, 분석 중 클립/곡 이동, 화면 종료 시 오래된 결과가 다른 트랙에 들어가지 않게 한다.

합격 기준:
- 원본 음성 파일은 성공·실패·취소·재시도 어느 경로에서도 삭제/덮어쓰기되지 않는다.
- 중간 위치에 놓은 잘린 클립을 변환해도 원곡의 위치에 맞게 들어간다.
- 피아노/기타/신스 결과 모두 재생·저장·MIDI/WAV 내보내기가 동작한다.
- 네트워크 실패 후 원본과 기존 음표가 유지되고 재시도가 가능하다.
- 초보 테스트 참가자 5명 중 4명 이상이 안내 없이 선택한 보컬을 악기 트랙으로 추가한다. 이는 출시 목표이며 현재 달성한 수치가 아니다.

### 3. 첫 곡 완성 흐름에 연결

이미 준비된 첫 곡 가이드 변경을 기반으로 “허밍/보컬 녹음 → 악기 선택 → 반주 선택 → 저장 → 파일 꺼내기”를 연결한다.

- 녹음 시작 전에 “목소리로 남기기 / 악기 멜로디로 만들기” 결과를 이해할 수 있게 표시한다.
- 저장한 보컬에서 MIDI 변환 버튼을 쉽게 발견할 수 있게 한다. 메뉴 깊숙한 곳에만 넣지 않는다.
- 반주를 자동 확정하지 않고 미리 듣고 선택한다. 고급 편집은 필요할 때 열 수 있게 한다.
- 전환·첫 저장·내보내기를 사용자 테스트로 먼저 확인한다. 분석 이벤트를 추가할 경우 기존 동의/고지/수집 비활성 원칙을 따르고 녹음·음표·이메일·파일 경로는 이벤트에 넣지 않는다.

### 4. 드래그앤드롭과 Mac/Windows

직접 변환 버튼과 같은 변환 서비스를 사용한다. 보컬을 악기 트랙에 끌면 “이 클립을 피아노로 바꾸기” 미리보기를 열고 확정 후 추가한다. 기존 악기 음표를 자동으로 덮어쓰지 않는다. 모바일에서는 버튼을 계속 제공하고 마우스/키보드 환경에서 드래그를 보조 수단으로 제공한다.

데스크톱 착수 순서:
1. Windows/Mac의 실제 녹음·재생·음원 엔진·권한·API·저장/내보내기·로그인·구독 지원을 조사하고 플랫폼별 지원표를 만든다.
2. 녹음→변환→악기 재생→프로젝트 저장/다시 열기→MIDI/WAV 저장까지 한 줄 흐름을 각 OS에서 먼저 동작시킨다.
3. 가변 창 크기, 마우스 선택/드래그, 단축키, 외부 파일 가져오기를 추가한다.
4. 서명된 설치 파일로 내부 테스트한다. Mac 모바일 앱 실행 가능 여부와 별도의 네이티브 데스크톱 제품 지원을 구분한다.
5. 모바일/데스크톱 간 프로젝트 파일과 보컬 자산을 함께 옮기는 방식을 설계한다. 현재 없는 클라우드 동기화를 출시 약속에 넣지 않는다. 결제/권한 방식은 각 배포 채널에 맞게 검증한 뒤 정한다.

## 검증과 출시 흐름

문의/내보내기/성능 개선과 보컬 변환을 작은 내부 테스트 단위로 나눠 검증한다. 검증된 로그인 수정과 준비된 40의 첫 곡 개선을 기준선으로 삼으며 롤백한 구버전 브랜치에서 새 작업을 시작하지 않는다.

재현 자료 → 화면 흐름/합격 기준 → 작은 구현 → 관련 테스트 → Android/iOS 실기기 → 내부 테스트 배포 → 사용자 확인 → 운영 배포 순서로 진행한다. 이번 계획 수립은 신규 내부 테스트 업로드나 운영 배포를 수행한 것이 아니다.

내부 테스트 확인 항목:
- 로그인, 게스트 생성, 기존 곡 열기, 저장·백업, 구독 복원은 회귀 없이 동작한다.
- 내보낸 파일을 실제 외부 위치에서 확인하고 앱에서도 재공유한다.
- 빠른 연속 음표 입력과 재생 중 입력에서 누락/지연을 측정한다.
- 보컬 원본 보존, trim/offset, 분석 중 취소/화면 이동/오프라인, Undo, 저장·재시작을 검사한다.
- 고객에게 변경 결과를 회신할 때는 실제 제공된 기능·테스트 상태만 알린다. 출시 전 일정이나 해결 완료를 미리 약속하지 않는다.

## 이번 소스 변경 검증

문의 주소 17개 파일을 변경했다. 자동 검증은 각 변경의 전체 diff가 기존 네 주소를 humtrack@gmail.com으로 치환한 결과와 정확히 일치하는지, 운영용 대상에 예전 문의 주소가 남지 않았는지, git diff --check가 통과하는지 확인한다. 정책 시행일·서비스 기능·가격·분석 설정은 변경하지 않는다. 문구·메일 주소 변경만 있으므로 전체 앱 빌드/기능 테스트는 이번 단계에서 반복하지 않는다.
